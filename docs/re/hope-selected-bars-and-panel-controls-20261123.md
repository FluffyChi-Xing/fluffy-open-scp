# 希望大厦选中态柱图、住宅入住与面板控件

## 选中态柱图

用户截图显示点选并打开面板时，标题为「希望大厦·容器测试1122」，塔身人口柱消失，面板仍显示 450 名游客。实装包 SHA-256 为 `3218e88bf96ba4089b0212ef6512e81dc5965fbe475ffa6278188d7a0fb06d1e`，菜单身份 `6E20E28F`。复核最终构建计划后确认，工作台地块 `label` 覆盖了输入 schema 中的 1123 标题，新包在游戏中仍显示 1122。截图中的 630 总接待容量也与新包叠加 450 观光与 180 商业容量一致。不能根据标题排除实装新版本。

零售 EXE 的 `6AA740` 将当前指定 Unit 引用存入槽 44/45，并通过 `7A8A00` 解析基座引用存入 46/47。启用模块分组时，它将目标自身的普通柱条可见位设为 1，同时将对应基座汇总柱条位设为 0。切换目标前恢复旧基座的汇总可见位。汇总创建 `6A9F90` 也按当前基座引用清除此位。渲染更新 `6AC400` 读取同一可见位。相关函数完整代码范围曾与实装 EXE 逐字节对照一致，实装 EXE 哈希为 `2b0aff527baa3aa536aca6c68332c208d1dbd904695f0f985d17d56b128d48ab`。

这条分支可以解释现象。普通容器选中的是基座，游客和劳工数据位于其组件，切换至基座自身普通柱图时可能没有对应条目。待在同一人口地图验证点选／取消点选的新版与原版基座对照。保留已验证的 `0FB2DB9A` 和 `30645625` 接线。

## 住宅入住

新版实装包住宅 Unit `F3839F43` 有人口容量 600、孩童与学生容量 75、初始空置位 22、入住入口 `999F8485`、低收入居民 bundle `D4C30C02`、地面接入 bundle `5D5EF1FF` 和满意度 bundle `323A4CF2`。住宅组件有原生步行与道路路径，但构建台账明确记录尚无该配方专用的普通车流接收接线。已查的原版科潘 Asset 同样有 Local/None 的步行和服务路段，因此凭这一列差异不能定因。

新版入住入口 `999F8485` 注册 `BBAAD3D0 → ED171D40`，居民事件 `C273CFD8` 能设置接入位 30。用户补充的实机截图显示人口图有 20 名在家居民，证明已有入住。需对照分档注册人数与返家事件判断剩余容量，单时点绿柱只表示当时在家人数。
