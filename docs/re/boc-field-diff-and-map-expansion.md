# BOC 与地图扩展：TGI 覆盖、字段差异和能力边界

记录日期：2026-10-10。

## 先把“字段级 diff”说准确

SimCity 的 `.package` 覆盖单位是完整的 DBPF resource，索引键是
`(type, group, instance)`，也就是 TGI。游戏加载多个包时，后加载的同 TGI
资源成为生效版本。DBPF 没有“只覆盖 property 的某一个 hash”这一层协议。

因此 BOC 的 `prop_diff_full.txt` 所说的“每个 Unit 只改一个字段”，含义是：

1. BOC 生成了 29 个完整的 `0x00B1B104` property resource；
2. 我们把它们与原版同 TGI 资源解码后比较；
3. 解码后的 49～104 个属性中只有 `0x0C8EE92F` 不同。

这对 OpenSCP 很关键：编辑器可以提供字段级 diff、预览和审计，但构建器最终
必须写出完整 replacement resource，并保留未编辑字段、数组顺序、未知字段和
引用闭包。

## BOC 样本的直接证据

- `tmp/boc/scripts_vanilla.bin` 与 `tmp/boc/scripts_main.bin` 都是 6,323,736 字节，
  SHA-256 都为 `FC189AECC0A986EBF7A41052D16408C108FB988982A1B30A80F4DB0B3025CBC8`。
  当前证据不支持“BOC 修改核心规则脚本”的说法。
- `tmp/boc/prop_diff_full.txt` 有 29 个 Unit，且恰好 29 处字段差异，全部是
  `0x0C8EE92F`（HASH_COST）。其中 9 个值为 `0x00400000`，20 个值为
  `0x04000000`。
- 这些 Unit 位于 group `0x40E1C000`，并通过其它 property 的 TGI 引用连接到
  模型、贴图、画刷和资源链。BOC 使用的是“新增/替换工具资产 + 高额成本”的
  资源组合，不是把区域高度场扩大一圈。

## BOC 真正成功的部分

### 1. 让盒外放置路径获得可用资产

游戏世界坐标是连续的；盒外位置仍可被地形、道路和模型渲染。BOC 提供专用
Unit、RW4 和引用资源，使放置工具有可消费的完整资产链。这个层面的成功属于
“放置资产与规则参数”，不等于扩大了城市模拟域。

### 2. 绕过部分经济/工具入口约束

高额 `HASH_COST` 把这些 Unit 变成专用的、几乎不会被正常经济流程误购的工具
对象。它解释了“能在盒外放东西”的表象，但不证明游戏接受了新的城市槽位、
城市边界或全图模拟。

### 3. 复用原版运行时坐标和渲染管线

BOC 没有新增区域高度金字塔、ED 生态金字塔、城市初始化表或新的区域注册键。
它依赖原区域的坐标、地形和渲染消费路径，因此成本低、兼容性较好，也解释了
为什么道路/模型类内容比城市模拟类内容更容易成功。

## BOC 没有解决、因而会失败的部分

### 1. 没有扩大区域资源覆盖

区域高度、生态、道路和资源采样仍受原始 region resource 集合限制。真正的新
区域或更大区域至少要同步 F0 高度 341-resource 金字塔、ED 生态场、区域描述、
模板注册和相关引用。只改城市盒参数不会生成这些资源。

### 2. 没有创建“单城市全图”的模拟边界

可见边长、城市盒、可建造检查、寻路、代理、服务覆盖、交通连接、出生点、存档
状态是不同消费链。BOC 证明的是放置/渲染链可越过盒边，不能推出人口、资源、
电力、水、污染、道路寻路和城市认领逻辑也越过盒边。

### 3. 没有闭合城市与区域的注册关系

原版城市仍由城市 property、城市高度场、区域绑定 key、模板 uid、地块并行数组
和选择界面注册表共同定义。删除或隐藏 UI 框并不会删除实体，也不会把区域外
坐标变成新的可玩城市。

### 4. 运行时状态可能需要回滚

BOC 的 Overplop/rollback 设计本身说明：放置成功与模拟状态一致是两个问题。若
只允许对象进入世界，却没有同步模拟实体、资源网络和存档引用，保存/重载或
模拟 tick 后就可能出现回滚、孤立对象或数据损坏。

## 对 OpenSCP 构建器的直接结论

### 目标 1 实验包为什么会“仍然显示 3 个城市”

2026-10-12 消费者追踪修正：下文对 Game registry 控制城市列表的表述过强。零售 launcher 的 `ShowTemplateDetails` 明确使用 `template.map.cities.length`，`RemapTemplateToRegion` 要求 boxes 与 cities 数量一致；游戏内 `ReceiveRegionData` 遍历引擎/API 返回的 boxes。registry 提供默认名称、介绍及评分，删除其中一项不会删除模板或运行时槽位。两份 registry 都存在，但不能据此断言覆盖另一份就能解决计数。详细证据见 [实际消费者与 UI 桥](map-consumers-ui-bridge-camera.md)。以下保留实验阶段记录。

这个现象不能再解释为“只改了一个字段所以引擎忽略”。目标 1 的资源闭包有
两个容易漏掉的层级：

1. `00B1B104` 地块并行表控制运行时 slot、城市 group 和坐标；五个并行数组必须
   同时保持索引对齐。
2. `67771F5C` Game registry 的 `kRegionalDefaultCityInfo.CapeTrinity`
   控制选择/认领界面显示的城市列表。逆向目录中存在两个同类型 registry 资源，
   只覆盖其中一个时，游戏可能仍从另一个实例得到完整的 `1026` 对象。

因此“包已被加载但仍显示 3 个城市”与“包根本没有加载”是两个不同诊断。构建器
现在应当对所有同类型 registry 资源执行相同替换，并在重开输出包后确认每个 registry
变体都不含 `cities:{1026:{`。`target1_add_registry_overlay` 已改为这个行为；模板
overlay 示例的 Rust 借用错误也已修复，否则模板资源并不能稳定重建。

即使选择界面只剩两个城市，已有存档中的区域状态和城市 EGB 仍会保留原城市。验证
必须使用新的区域选择/新存档，并分别检查选择界面、进入区域、认领和保存重载。

地图 Mod 构建应把每个输出声明为一种操作：

| 操作 | 需要覆盖的资源闭包 | 当前可行性 |
| --- | --- | --- |
| 原始地图名称/介绍 | 注册表 + locale 资源 | 需先做 TGI/字段闭包验证 |
| 选择图/封面 | 实际 UI 消费的 raster 与引用 property | 需定位真实消费者 |
| 城市/伟工屏蔽 | 模板、地块数组、绑定 key、启动状态 | 不能只删预览框 |
| 高度替换 | 341 个 F0 高度资源及原始 tile 拓扑 | 已有可验证 writer |
| 资源画刷 | ED/资源场及 transform、分辨率、目标字段 | 需按字段闭包写回 |
| 盒外放置工具 | Unit + RW4 + 引用资源 | BOC 已证明思路可行 |
| 单城市全区域模拟 | 上述全部 + 模拟边界/寻路/存档链 | 不能由 BOC 证据授权构建 |
| 独立新地图注册 | 区域注册、模板、城市初始化、全部场资源 | 当前未闭合 |

构建器不能把“存在一个同 TGI 的 overlay”报告成“地图扩展成功”。成功标准
必须至少包括：资源重读、引用闭包、选择界面、进入地图、模拟 tick、保存和重载。
其中任一步没有证据，就应在 IM/构建结果中标记能力缺口。

## 下一步实验顺序

1. 找到一组 BOC 专用 Unit 的原版同 TGI 资源，做完整 property 字段 diff，并记录
   `HASH_COST` 之外的引用闭包。
2. 对一个道路/工具 Unit 做最小 overlay，验证“能放置、能保存、能重载”三项是否
   同时成立。
3. 对一个区域描述字段做单字段 replacement，确认它只改变 UI、还是也改变
   runtime bounds。
4. 对一个城市绑定 key 做最小实验，分别观察选择、认领、进入、模拟和存档。
5. 只有第 4 步闭合后，才设计 OpenSCP 的城市槽位和单城市全图 writer。
