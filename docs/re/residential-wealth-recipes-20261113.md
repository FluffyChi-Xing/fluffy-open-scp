## 核心循环

| 阶段 | 地面住宅的规则接线 |
| --- | --- |
| 外部接入与空置 | 自长住宅通过 `5D5EF1FE` 处理施工和道路连通，科潘的地面放置接线为 `5D5EF1FF`。入住 sink 的 key bin 为 `A9ECEDE4`，要求本地空置位 22、可接入位 30 等条件。科潘在 Unit 上初始化 22，居民 bundle 的事件 `C273CFD8` 和施工规则路径会设置 30。 |
| 派发与入住 | 城市派发链 `6734F3E9/352DE952/5B3063FB` 把 `A9ECEDE4` 带入事务并分别指向地面三档入口。地面 $ `999F8485 → BBAAD3D0 → ED171D40 → … → 337A4D2F`，$$ `A7974BCE → CDA8B193 → ED171D43 → … → 337A4D2C`，$$$ `8D9AF497 → A7A6370A → ED171D42 → … → 337A4D2D`。规则从剩余容量填充总人口、对应档的在家劳工和消费者、孩童等。科潘另用 `999F8484 → BBAAD3D1` 接同一 W1 填充链。 |
| 按档出门与返家 | $ `D4C30C02`、$$ `A8CB9DE1`、$$$ `AC8B8A48` 声明各档居民资源。劳工派发根是 `07A49947/2E5C8CE0/E9FC4C3D`，购物是 `7A41EB3A/9079DE5D/36E2B400`。购物事务扣购物 token、钱和在家消费者，通勤事务扣在家劳工。两种事务均可减少 `TotalResidents`，返家规则恢复本地计数。因此读取人口时要注明人在家还是在途。 |
| 孩童与学生 | `0A7917CC` 以倍率 1 同时设置 `Kid`、`Student`、`StudentTokenE2/E3` 的容量。入住链直接填 `Kid`。三档居民 bundle 均注册 `5BB894A1`，后续 `CC334C6E` 扣一个 `Kid`、写在途 `KidE2`，候选含小学 sink `78B96709`。住宅的 `5770FEDD → 57537A37 → … → 414C4DED` 处理返家知识载荷，`26CCFB8F` 增加 `Student` 和 `StudentTokenE2`，`00CB5CC1` 进一步读取 Kid 槽。到校人数还受时段、道路、学校空位与事务是否成功影响。 |
| 日常、迁出与补充 | 各档有自己的幸福、病患、返家及税务接线。普通住宅的三条幸福/税务入口 `64BA425E/96C14CD5/68BEC5D4` 分别读取各档全局阈值。分档渐进规则及 `E9D6ED62/61/60` 使用不同的城市供给，向对应的在家资源和 `TotalResidents` 补人。密度升级和区划生长属于自长宿主。 |

巨塔三档入口分别是 `78A730CD/CE/CF → BBAAD3D1/CDA8B192/A7A6370B → 81AA8640/43/42`。对应 `EBFC1753/50/51` 还维护塔内人口容量，使用相同的三列角色容量，并注册带额外计数处理的学生返家入口。普通与菁英的 W2 塔层共享入住和生活接线，施工模块不同。巨塔的 W2/W3 容量 bundle 与地面居民 bundle 都会注册 `5770FEDD`，所以新地面配方使用基础游戏的分档入住和返家入口。

## 可控的角色容量

- **劳工与消费者**由两个 Float 分别绑定到各档居民资源，入住规则直接使用这些槽的剩余容量。工作台用总人口和居民劳工容量推导消费者容量，保持所查样本共同的 `workers + shoppers = population`。这些是容量，实际每日派发还受城市需求、车辆及通路限制。
- **孩童**可以单独调 `0A7917CC`。它与劳工/消费者使用独立资源槽，原版样本也保留独立的孩童配额，不能将四项相加当作总人口。
- **学生**的资源容量和孩童共用 `0A7917CC`。本轮提供孩童容量联动。要独立控制学生上限，需提供独立的 Property 绑定，并核对派发、返家与按 Kid 调整学生数的规则。固定百分比实际到校还需要改变派发和接收条件。

## OpenSCP 配方

新增 `ground-residence-w1-v1`、`ground-residence-w2-v1`、`ground-residence-w3-v1`，每个叶子选择一种财富档。三个选项分别使用 D2 模拟模板的默认人数和居民 bundle，抽取共用住宅状态、服务与学生接线，搭配科潘的地面施工接入。保留宿主的菜单、模型和 Lot 接入。已有科潘及巨塔 profile 保留原路径。新叶默认选地面 $。

选定原版记录以 `reference/sc5-packager-0.8.0/behavior_profiles.py:62–95,106–137` 的叶级优先取值、应用、回读为参考。配方使用分档入住、劳工和消费者接线，排除竞争的其它档及巨塔入口。回读验证有效写入、启用项唯一、排除表、空置位和原有 Lot 路径要求。每档收入是单 Unit 的独立选项，混合财富需要分别处理共享的人口资源和同名返家 sink。

工作台中的总人口为整数，劳工和孩童可指定 0 到总人口之间的整数。留空时按所选 D2 样本的比例缩放并四舍五入。合成住宅的幸福和服务参数使用所选 D2 样本的固定原值。Ground profile 是地面可放置建筑的模拟配置，尚待各档独立验证新放置、入住、通勤往返、购物往返、上学返家、迁出后重新入住。
