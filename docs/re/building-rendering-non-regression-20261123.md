# 所有建筑功能必须守住的渲染验收

用户于 2026-11-23 重申：假内景、晚上开灯、贴图等都是无论调整什么其它功能都不允许回归的要求。已固化到根目录 AGENTS.md「建筑渲染不可回归」，并非仅对本次希望大厦有效。

当前实现中已有的必要闸门：

| 验收内容 | 当前检查入口 | 证据边界 |
| --- | --- | --- |
| 原生内景源、窗户列及房间状态 | `author_materials.rs`、`source_uv.rs` | 不允许退回不完整源或丢失原生材质参数 |
| 原生六槽材质、模型与纹理绑定 | `material_gate.rs`、`material-binding-contract`、`written_contract.rs` | 最终模型和纹理资源须实际存在且布局、绑定正确 |
| 假内景与窗灯控制器、Graphics→Lot 继承 | `interior_lighting.rs`、`written_contract.rs` | 必须与模拟侧激活接线共同验证，不能只看 Bool 开关 |
| 夜间灯光周期 | `native_profile.rs` 原版夜间周期及已有回归 | 正确周期为 `12952639`，不能写回曾误抄的 `12956239` |
| 容器宿主生命周期与激活 | `behavior_container.rs`、`interior_lighting::verify_landmark_activation` | 保留普通宿主基础生命周期，不能只复制巨塔排除项 |
| 模块统计柱按基座汇总 | `behavior_container_bars.rs` | 宿主和每个组件须接入原版分组，前置及写盘均检查 |

现有闸门不能被宣称为已覆盖所有渲染风险。后续发现缺口必须先补到通用契约和有意义的反例回归；不能为某一栋建筑写临时参数补丁。新行为和新架构不得绕开这些既有检查。

不涉及渲染的改动，应沿用本次已执行的证据方式：先验实际包身份，再比较解码资源和具体属性差异；除模型/纹理外，还要核对会驱动窗灯的 Unit 生命周期。修改模拟状态也可能影响渲染，不能用“模型字节没变”证明不会黑灯。

若改动相关接线，静态契约、包字节和用户游戏验收分别记录。未通过对应检查不能作为交付通过；尚未由用户启动游戏验证的候选，必须明确保留待验收状态。没有新增自动启动游戏的流程，也不放宽存档隔离或包归档规则。

本次仅固化用户的长期约束并整理现有闸门，没有修改已验证渲染实现、重打包、部署或更改游戏文件。
