# 行为叶子可调属性

| 节点 | 可调输入 | 模拟绑定与边界 |
| --- | --- | --- |
| 住宅 | 财富档、总住户、居民劳工、居民消费者、孩童与学生容量、入住幸福、幸福上限 | 总住户 `0A7917CB`。居民劳工与消费者分别写 `0E33502E/0E335022`，合计等于人口。孩童和学生槽共用 `0A7917CC`。幸福写 `0E546790/91`。地面配方默认按已读回的 RCI 样本随人口设定为 1 倍和 11 倍。 |
| 商业 | 三档居民顾客、商品容量、三档商业岗位、最低开工人数 | 混合商场用分档接待容量绑定。商品 `0DA3EE15`，岗位 `0A7917C5/6/7`，开工门槛 `0A7917C8`。全部岗位输入留空时沿用配方默认行为。 |
| 办公 | 三档岗位、最低开工人数 | 岗位与建筑属性叠加。同一 Unit 的最低开工人数取两边的较大值。分组件时各自按自己的门槛工作，建筑仅保留一个启停按钮。 |
| 观光 | 吸引力、总接待容量、三档游客配额、三档游客收入系数 | 吸引力 `0E542F39`、总容量 `0AD6A725`、分档配额 `0D8C29F6/9FE/A01`、分档收入 `0EE2A50D/E/F`。实际到访和消费取决于城市客流。 |
| 酒店 | 客房数 | `0E2660C6` 写入原版中收入酒店接待规则。 |
| 教育 | 校内接待容量 | 学生容量与教育配方、步行路径和入学/返家规则共同工作。住宅侧的学生来源容量与学校的座位容量是两个设置。 |
| 公园 | 吸引力、两组地价值与对应收入档 | 地价输入属于周边影响。吸引力在同 Unit 的原版观光配方存在时由观光控制。 |
| 地价 | 中、高收入地价值 | 新配方对应两档影响，旧配方保留各自的输入。 |
| 树木 | 树木行为启用 | 绑定原版树木 bundle。 |

住宅的幸福输入控制模拟库存，满意度会继续受购物、税率和服务影响。学生容量沿用共享槽，实际到校还依赖出发、路径和学校座位。商业的到货周期、利润规则和访客停留时间目前由原版配方接线决定。地面住宅和巨塔住宅的来源见[满意度对照](residential-happiness-rci-megatower-20261123.md)。

混合容器将建筑属性中的有效岗位编译成无模型的已连接子 Unit，办公、商业、教育等组件各自保有自己的岗位来源。建筑岗位组件使用通用招工配方，不提供自己的菜单或控件。创建楼栋时的入口、组件总开关与数据图汇总仍按既有容器契约验证。

## 打包和回读

- 单办公 Unit 的建筑岗位 `300/100/5` 和办公岗位 `200/100/50` 合计为 `500/200/55`，包回读为 755 个岗位。
- 六行为测试包单独回读建筑、办公、商业和教育岗位分别为 `300/100/5`、`200/100/50`、`20/30/10`、`5/2/0`。同时回读住宅 600 人、420 名居民劳工、180 名消费者、75 名孩童与学生容量、幸福 700/6800，以及观光收入系数 12.5。
- 六行为测试包 `967f2362…` 与同身份基线 `380308f9…` 逐 TGI 解码比较。差异只有新增岗位 Unit/Asset、宿主组件表，以及上述住宅、商业和观光字段。自定义面板测试包 `5ecafe00…` 与同身份基线 `e631e858…` 的既有资源仅有宿主组件表增加一行，面板运行包 SHA-256 一致。两组包的模型、贴图、材质、Graphics、既有渲染控制属性和既有面板资源均保持一致。
- 希望大厦实装 GOLDEN 哈希复核为 `2deb7281…`。本轮只在工作区构建和回读，游戏内满意度、招聘、照明和面板的运行验收仍需实机测试。
