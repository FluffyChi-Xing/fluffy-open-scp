# 商业区酒店化与三个工作台行为（2026-11-26）

## 原版商业区如何选择酒店

从已核对哈希的基础包 `SimCity-Scripts_287520926.package` 重读 AEB `08068AEB:40800200:622B9CD7`。95 条 ZoneRule 中，下面九条的目标 Zone ID 能逐一对应到酒店模板 `48E0C000` 的 `092F9CB4`。原版引擎按该 Zone ID 进入区划放置候选；酒店模板另挂对应财富档的住宿入口和空房属性。

| 财富档 | D1 / D2 / D3 酒店区划规则 | D1 / D2 / D3 酒店模板 | 各密度原版空房 |
| --- | --- | --- | --- |
| W1 | `5F78D8AE / 5F78D8AD / 5F78D8AC` | `AF6888D3 / AF6F44EC / 6F6CA145` | 14 / 76 / 710 |
| W2 | `6D709FD5 / 6D709FD6 / 6D709FD7` | `97229A2C / 971A4B13 / 571DB83A` | 12 / 68 / 670 |
| W3 | `93731A7C / 93731A7F / 93731A7E` | `B0176A55 / 7014C68A / 70128823` | 10 / 60 / 620 |

九条规则都保留常规区划环境条件，并检查三项酒店专用条件：

- 本地酒店图层 `E3BFCDDD ≥ 1`。原版地标父模板 `4E01E311`、罗马赌场父模板 `9F25895C` 等引用 `BD999F77`，它以 `0EAB22D0 / 1A0D7683 / B51E5982` 写入和撤回该图层。酒店自己的 `8748B5A5` 也会读这个值。
- 城市全局 `539CA551 ≥ 1`。`BD999F77` 同时以 `AEDD41C3 / D8978685` 登记和撤回这个量。
- 对应财富档的城市计数达到 **200 / 250 / 50**，资源分别为 `1AA9D48F / 4F5740DA / DE20D795`。旅游事务链 `7793CE55/56/57` 各加 1；住宿提供器 `729A6625/26/27` 各有相应的扣减规则 `9962B361 / 93996808 / 21CEA0DB`。这是选型需求计数，阈值不能解释成酒店房间数、地标距离或当前房客数。

静态证据将此前「地标旁会出现酒店」具体化为 **影响图层＋全局登记＋分档需求＋原版区划候选**。对已营业普通商店，何时重建、能否原地替换、原经营状态如何归档，仍需观察旧新 Unit 的身份、占地与状态；引擎另有地块替换优先级判断。

复查锚点：AEB ZoneRule 段首条偏移 `4339037`；酒店九条为零基序号 55–63。记录中的地图和全局输入以过滤下标索引阈值表。开发反编译 `SimCity-dev-ida.c` 第 693249–693299 行采用下限包含、上限排除的测试，第 1058735–1058741 行把候选的 Zone ID 和 Unit entry 送入放置数据。包身份见[上轮研究](casino-hotel-controlnet-followup-20261126.md)。

## 构建处理器和运行取数

保存后的工作台图经 `build_queue.rs` 的项目入口进入 `workbench_logic.rs`，在 `behavior_units.rs` 确定宿主、业务 Unit、客房发布模块和岗位归属后，再生成资源。新增处理器走同一入口。写盘和回读同时核验绑定；预检失败沿现有拒绝记录进入 Actions 并带原始错误和阶段，项目采集也能找到同一失败。编译失败直接结束本次构建。

- **博彩。** 新增处理器使用原版接待、周期补货和 `3B8EEF5B` 收益规则。已核对 `CCD1142B/414F8467` 都读取营业模式 `4B16C93D`，移除规则 `E20CDC92` 成对撤回本地与全城收入。开放配方前完成营业模式初始化、停业清客与重开补货闭包。博彩与客房同配时由一个接客 Unit 持有博彩库存和住宿库存，客房只向该 Unit 发布及撤回容量。宿主维护费和全城收入各记一次。
- **住宿。** 保持 `behavior_hotel.rs` 现有路径的兼容性。新配方以 W1/W2/W3 的 `729A6625/26/27` 分档办理入住。独立房间在接客 Unit 本地初始化。博彩附属客房走原版动态发布。`0E2660C6` 还可能被纪念品容量消费，校验规则必须检查两方是否共享参数。构建闸门核对房间数量、接收单元、同档空房扣减与退房归还。区划自长配方保留其商业模板选择和重建流程，手动放置配方仅接入住宿闭环。
- **ControlNet。** 新处理器以 `61EFC000:74AFA83E` 为供体，保留实际工人提供器、`8936DD32` 的刷新、产出和 `6454E4DA → 61EFC500:26A2E32F` 的径向发放。根据完整 TGI 解析 EP1 原生依赖和 AEB，检查键、作用域以及安装版本。检测岗位统计和实际派工是否同源，防止把同一岗位分别计为公共员工和生产员工。暂以原版覆盖作为配方参数，开放覆盖编辑前核实距离字段与单位。停机、恢复、拆除及消费者端回落需保留原生事件。

三者共用现行宿主的水、电、垃圾、污水、激活和渲染契约。构建明细和运行采集需随最终宿主和组件写出指标来源，包括 TGI、实际 Unit 归属、本地／连接／全局范围。博彩人数、房客和 ControlNet 库存分别从对应资源读取；消费者未解析时保留原始诊断。

## 手动放置配方的废弃闸门

所有新增 plop 行为的宿主和业务单元都要剥离自长经营废弃。对 RCI 供体，先追到实际状态写入和替换目标，再只移植已核实的业务规则。现有许可范围内的正常关停、复工、缺货、顾客离场、居民不满与迁出都需要继续工作。

- **住宿的已复现静态入口。** 现有中收入 `behavior_hotel.rs` 启用 `6827D126`。本轮重新沿规则闭包追到 `9D061D19 → 23B3C746 → D0981716 → 3021C1A4 → 4684DC06 → 8C10B920 → B516ED75 → CCF91580 → 7362794B → 85BF39A2`。后二者会写经营废弃位 `0x800`。新的手动住宿配方必须断开整个废弃入口，保留入住、退房、空房更新和停业清退。旧保存的 `rooms` 与财富档语义保留，但生产构建需迁移到剥离废弃的配方并通过回归。
- **商业与住宅的现行防护。** `behavior_copan_base.rs` 已拒绝在手动商业组件启用 `6827D125/126/127`，并验证原生 plop 创建提供器 `406CCC43` 和失败替换目标。住宅的原生 `IsToy` 门控需要和不满迁出、返家及后续搬入分别验证。对新增 RCI 供体，核对同一实例的旗标生产者和规则条件后再借用门控。
- **构建及写盘回读。** 对最终生效的本体与组件闭包核查启用／排除表、继承、动态注册、成功和失败分支、状态事件以及主动 `FailUnit` 替换目标。防止从其他提供器重新引入废弃或把宿主切成空置／废墟。仅删除一个字段或隐藏面板状态不足以通过。剥离经营引起的废弃时，保留现有渲染控制器和与整栋关停相关的合法状态。
- **运行验收。** 让博彩零游客或零收益、住宿长期空房、ControlNet 无工人或无消费需求，并验证整栋及组件在这些条件下保持原身份、无经营废弃，恢复供给或客流后继续工作。区划自长酒店的原版重建、替换与退出另行验收。

## 第一批实现与静态验证

现有中收入手动住宿处理器已移除并显式排除 `6827D126`，构建及回读均核验排除项、既有原生入住接线和客房配置。保存的 `rooms` 保持兼容，缺省仍为 68。带住宿的构建使用新缓存版本。已定位的 RCI 废弃周期没有住房容量绑定或入住 sink，二者仍从 `729A6626` 提供。

面板库已新增「客房入住」控件，包含中收入住客数、当前空房及配置容量。独立住宿直接读取本体，分组件配置由构建器写入接客组件选择器，面板按放置实例解析并读取本地值。旧 `hotel-guests` 保持原有绑定。双语面板测试覆盖空房、满房、缺值以及切换语言。

已用保存后的项目通过同一生产编译器离线构建：旧住宿配置（68 间、旧控件）、新住宿配置（84 间、新控件）、住宿＋观光、商业＋独立住宿组件。写盘核对了中收入入住提供器、废弃排除项、客房数和组件选择器。只有绿化的项目选择入住控件时，预检返回 `PANEL_BEHAVIOR_REQUIRED:hotel-occupancy:hotel`。

同一独立住宿项目的新旧离线包均重新核对 SHA-256。共同的 21 项资源中，19 项解码 payload 一致。差异仅为 Unit 的启用／排除表和 Asset 的悬停／点击面板绑定，模型、纹理、材质和 Graphics 资源一致。该对拍覆盖本次独立住宿离线样本。尚无实装包对照、游戏运行记录或实时采集，不能据静态对拍判断营业恢复及夜间表现。

下一批供体核对补充：罗马赌场和普通赌场样本均启用 `30645625`，该提供器声明 `4B16C93D` 的原版容量与初值（均为 3）。可据此追踪既有宿主的营业模式和赌场清客事件，避免把多个相同模式提供器并挂。EP1 接收端 `B4E28D19` 已定位到 `61EFC700:72567720`，它消费传输 token 并向本地写入 ControlNet，仍需确认消费原型的完整注册及停复机闭包。博彩、ControlNet 生产及其面板控件尚未接入生产。

## 中国银行「观光＋博彩」交付

「行为叶子」已支持带原生观光的博彩组合。观光叶子提供吸引力、财富配额和总接待位，博彩叶子提供分档赌位和费率。两者使用同一原生旅游接客单元。生产预检只接受这两个业务叶子，公共服务及建筑信息照常配置。现有保存的纯观光和住宿继续沿各自路径。

博彩配方在原版地标接待路径上采用普通原版赌场 `40E0C000:3CE0F852` 的 `30645625` 营业生命周期、`CA726CB4` 清退、`352F4263` 空住宿库存和 `3B8EEF5B` 结算。后者接管赌场本地及全城收入，排除旧地标财务和 RCI 经营废弃周期。构建期和回读验证绑定唯一、三档参数、状态以及原生渲染闸门。统计面板新增「赌客人数」和「博彩收入」。收入直接读取本地 `IncomeFromCasinos`。项目采集探针也读取这项收入、已有三档游客 bin 和新增三档可用赌位。

离线验证使用 `D:/openscp/mods/中国银行` 保存内容的工作区副本，保留真实模型、材质、场景和路径。实际项目的菜单未启用，且原图包含观光、地价、绿化、办公四叶。副本启用独立公园菜单，移除地价、绿化、办公及办公面板控件后加入博彩。纯观光对照和观光＋博彩均通过与 Actions 共享的项目发现、保存图编译和生产构建。缺观光的博彩图在入队前返回 `CASINO_TOURISM_REQUIRED`。

中国银行同源纯观光及观光＋博彩包复核 SHA-256 后逐项对拍。13 项模型、材质、纹理资源以及同身份 Graphics 资源的解码内容一致。纯观光对照使用分离组件，博彩组合由宿主直接运行，因此组件 Unit/Asset 与统计绑定有预期差异。整栋的启停、日夜显示、博彩到访、收入和日志采集仍须在游戏验证。此处无部署动作。
