## 为什么这一版会触发

对拍归档基线 `2deb7281…` 和实装 `3218e88b…`。宿主及原有四个组件的地块路径坐标、索引、作用域、连接方式、车型接收配对一致。新版新增零售、住宅和建筑岗位三个模拟组件，并把同一组入口路径交给各组件。旧希望大厦的四个组件没有这组三档零售接待，也没有新版住宅发起的购物事务。

实装零售组件启用 `1C1F5978/7B/7A`。共享空位由 180 容量初始化，三个财富档在店顾客的独立上限均为 60。原版街道 sink 资格使用共享空位及本地条件。自定义分档上限由进入后的原版规则执行时检查。以 W1 为例，`885CF9D2` 要新增 `ShopperW1`，因此即使共享池仍有空位，W1 达到 60 也能让该入场规则失败。失败链 `AC83C7DB → 2DBD5243` 有在原入口类型再次派发的原版操作，引用的 transport ID 是 `14A0C36E / FC0CC116`。这是可以从实装配方和原版 AEB 证实的一种拒绝后重走路径。尚无现场交易记录确认截图中的个体触发了该分支。

离线构建两个独立菜单对照包，保留同一模型、路径及建筑／办公岗位，分别去掉住宅或去掉零售。仅零售对照 `CEB3AE36 / 9dbcbc5b…`，仅住宅对照 `FBA45BBB / df0ff713…`。仅住宅对照包含最新的返家接收绑定。两个包均通过构建与读回，未部署。运行期可先验证仅零售是否复现，从而区分住宅导出的购物流与零售自己的拒绝重派。
