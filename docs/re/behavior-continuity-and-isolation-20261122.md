# 建筑持续运营与独立行为组合：重新界定验收

2026-11-22。状态：发现并补全原生观光遗漏的事务生命周期属性；运行时根因尚未全部确定。本记录的单体调查未部署测试包，后续独立单元实现与工作区原型见[独立行为单元组合](independent-behavior-units-20261122.md)。

## 本次缺陷报告

用户报告观光建筑偶尔收入约 2500/h，多数时间为零；商业仅短时有顾客；住宅因不快乐迁出；多种完整行为无法独立组合。截图中的佩翠安纳制药为游客 13/300、收入 130/h、维护 2500/h。截图是一个时点，全天变化来自用户观察，两种证据分别保留。

先前的包回读、入住成功、短时间成交，均不构成持续运营验收。人数容量不是每日到店量，接到第一批人不是完整闭环。既有 GOLDEN 标记只代表用户当时确认的行为范围，不能据此扩大为跨日运营全部通过，也不能因此覆盖或降级原包。

## 观光

`src-tauri/src/asset_build_m1/behavior_tourism.rs` 的原生 profile 挂接东京塔四个 bundle；`apply` 写吸引力、三档配额、共享接待容量、纪念品容量及收入参数。`verify` 核对菜单、启用/排除和道路接入，没有验证运行期需求发布、游客接收、离场后释放、纪念品恢复及跨日收益。

既有 [巨塔研究](megatower-behavior-controls-20261113.md) 记录观光冠楼的发布与三档接收链；[威利斯研究](willis-tower-landmark-mechanism-20261027.md) 记录地面地标的继承和营运底座。应对最终有效属性及规则作完整生命周期对照，不能以吸引力、容量或四条引用相同代替。

当前未确认是补客不足、营业中断、库存、空位释放、离场周期还是不同供体机制。不能先调整驻留时间或收入系数。即使正常补客，城市游客供给不足时也不保证全天盈利。

## 商业

[商业调查](commercial-wealth-recipes-20261114.md) 的既有现场采样覆盖 tick 10570–10672：持续营业、有库存、入口有效、利润净增，在店 W2 顾客为 0–3。这只能证明那段时间发生过交易，不能否定本次全天客流不足报告。

接下来须同时记录实际营业状态、分档库存、共享空位、分档人数、入口有效容量、累计成交及同档原版对照。居民购物派发候选可能不同，因此城市有同档居民也不代表每次派发都能选择本楼。巨塔商场还另有塔内客源；地面移植不能自动获得该客源。

## 住宅

已确认一个值得追踪的配置差异：`behavior_residence_wealth.rs::select` 随总人口推导居民劳工和儿童；`fields` 将人口容量写为作者值，却固定写 W1 幸福参数 60/660/450、W2 30/330/270、W3 10/110/78。它们来自对应小型 D2 样本。不能仅因它们看似与人口成比例，就直接乘倍数；须先确认三个参数各自是容量、初值、阈值还是周期消耗输入，再检查完整幸福与迁出链。

[住宅调查](residential-wealth-recipes-20261113.md) 已注明各档通勤、购物、上学返家及迁出再入住尚待验证。旧巨塔入住 profile 另有双学生返家入口，见 [冲突研究](behavior-leaf-bin-conflicts-20261113.md)。需要先从项目台账确定用户实际使用的 profile，避免将旧巨塔路径的问题套到新地面住宅上。

运行时需区分：暂时外出导致在家人口下降、真正迁出、返程未能接收、幸福耗尽。保留正常城市服务和税率影响；禁用迁出或反复灌满人口不算修复生活闭环。

## 巨塔提供的隔离方向

现有编译路径将多个行为叶子挂到同一个 Unit。同名资源声明会合并，属性绑定可能覆盖，同名 sink 可注册多个规则；这不是隔离容器。`behavior_conflicts.rs` 只比较部分 bundle 的资源声明，既有真实共享，也有未覆盖的 sink 和字段冲突，不能简单删除告警。

原版普通/菁英塔基、楼层有不同的模拟 Unit；楼层带内部路径、模块关系和 EP1 共享依赖。已定位的首层放置项用 `07E0AD0A` 引入公寓与公共子单元；楼层还共享 `E678CDF8`。这支持以“一个可见宿主 + 多个独立模拟子单元”作为待验证方向，不证明普通地面宿主只添子单位数组即可运行。现有 `author_tourism.rs::profile` 还明确拒绝供体默认子模块，新组合必须在新模块/新路径实现。

原样提取原版子单元创建、归属、道路与内部路径、启停、拆除、保存恢复和费用汇总契约后，才能决定地面宿主是否可复用。不得把所有 Local 资源换名：城市事务、全局资源和通用规则仍依赖原版资源身份。每个子单元应独立拥有业务资源，宿主负责经过原版证据确认的连接及汇总。

## 后续修复的闸门与验收

1. 确定每个受影响项目和配方；从 build ledger 找成品，再核 MANIFEST，并对实际部署包与构建产物分别验 SHA-256。本文没有比较任何当前部署包，既有文档哈希不是本轮验哈希结果。
2. 沿完整父 TGI 展平最终配置，按 A2–A5/B2 和绑定顺序审计资源、sink、规则、初值、参数写入者、时间和路径。缺字段/缺资源类修复同时添加构建硬闸门；静态闸门不冒充运行时证明。
3. 单行为先完成跨日采样：建议预热后至少连续三个完整游戏日，记录补客/返家、库存与空位恢复、营业、迁出原因及收支。同城同档原版作对照，指标阈值根据原版与供给确定。
4. 单行为稳定后验证多行为组合：一种业务的库存耗尽或恢复时，不得误改其它业务的本地资源和规则。建筑只有一个总开关，关闭和开启应同时作用于所有行为；整栋拆除应清理全部内部单元。换第二个建筑身份复核通用性，并验证保存重开。分行为开关不是用户需求。
5. 新包只用独立菜单；先备份真实 Games 保存根，遵守健康样本城市与测试包集合隔离。归档/部署通过 `scripts/archive_test_package.py` 登记。仅用户启动游戏，菜单冷启动通过后才在一次性城市测试。

## 续查：已证实的观光参数遗漏

从佩翠安纳 `.build/ledger/eadca525f70f04904ff7b363f25db70931e9894122cbcced29b3a9381f48a91b.json` 定位产物后，分别计算构建包和当前实装 `000_OpenSCP_medical_building.package` 的 SHA-256，两者均为 `fb0958381e0b037205f431b377f763e9c0791a424d04915807f36e138529e365`。MANIFEST 中未检索到该完整哈希，不能据旧的 `e4ecdbd2` 记录描述当前实装身份；本轮没有修改台账或部署。

新增只读探针 `probes/property/tourism_lifetime_audit.py` 回读当前包及全部父模板，确认有效配置缺少 `0D9114D4`。东京塔 `00B1B104:40E0C000:084DB48F` 则明确声明 `Vector2(120,120)`。原版基础脚本包本轮 SHA-256 为 `77ddced4a23a818673e44c19649732390d8771bc5a1434583032e5841baedd04`。完整审计输出在 `tmp/tourism-lifetime-audit-20261122.json`。

基础 AEB 经既有 `parse_rules.py` 精确解析（SHA-256 `a388e3c15080a4721e7d0047da180f6ee9f38292060c67892fa34b952564c381`）。三个游客接收规则 `64E8EB50/51/52` 的 prop specialization 均引用该字段，opId 26、data16 1。零售引擎反编译 `tmp/dev-sample-analysis/SimCity.unwrapped.exe.c:667629` 的 `SpecialiseUnitRule`，在 `:667710` 读取 Vector2，`:667824` 将它赋给目标 transport op 的 `mLife`；缺字段时跳过这次覆盖。由此可以确定是迁移漏项，尚不能从静态代码确定缺项在本城导致的实际驻留时长或收入变化，也不将 120 擅自解释成游戏分钟。

修复放在新模块 `behavior_tourism_lifetime.rs`：仅在原生观光构建路径补全缺项，复制既有东京塔快照中的整个 Property（含编码）；已有正数且有限的 Vector2 保持原字节，类型错误、非有限或非正值阻止构建。补全后编码并回读检查。`behavior.rs` 只增加新模块调用和构建变更记录，原有接收及离场规则不改。复制方式对应基准 `behavior_profiles.py:62–95,106–137` 的选取/应用/回读流程；新增属性的依据是上述已复现迁移缺项。

## 续查：隔离的引擎证据

`SimCity.unwrapped.exe.c:647416` 的 `CreateSecondaryUnits` 为每项独立调用 `StartCreatingUnit` / `FinishCreatingUnit`，随后在 connect 标志开启时调用 `ConnectUnits`。`:699463` 附近读入子单元表，默认 chance=1、connect=false；因此不能只加子单位 ID 而遗漏连接列。表对应 ID `07E0AD0A`、偏移 `07E0AD0B`、旋转 `08635E14/15`、概率 `08635E13`、连接 `0D363DF3`（十进制表 ID 换算）。

`ConnectUnits` (`:634933`) 维护双向 connected-unit 引用、更新双方 sink 容量并回调 `UnitsConnected` handler。这证明独立模拟实例及连接机制存在；尚未证明它单独提供地面外部道路、共享启停或拆除级联。需要进一步核对原版完整连接契约，才可新增组合构建器。

住宅参数目前追到 `323A4CF2` 的容量/初值绑定：`0E546791` 供 `HappinessToken/HappinessTokenLast` 容量，`0E546790` 供部分幸福等级槽容量和初值，也用于入住规则 `337A4D2F` 的本地幸福输出；所以它们不是纯显示参数。但当前实装住宅包为旧巨塔测试包（本轮实测 SHA-256 `041e79049b1da236b0fcfe361d5c3aeea31a43040b31ee3712898ee68ec46529`），不能把新地面住宅 profile 的固定参数差异直接归为该包的迁出原因。

未修改 SQLite 启动边界，未操作游戏、存档或实装包集合。剩余项是住宅当前成品与构建身份对应、生活规则与游客补客运行时归因、完整子单元契约及跨日游戏验收。
