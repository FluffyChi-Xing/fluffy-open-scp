# 地图编辑器：资源证据、Flow 节点与可重建文档

记录日期：2026-10-08。需求来自用户的区域选择页与城市选择页截图。

## 阶段与目标

当前任务仍是实现、核对 3D 地图预览。在过程中收集下述信息，为后续编辑器提供依据；
本文件不表示 Vue Flow、schema 编译器、全地图城市或新地图生成已经实现。

用户确定的开发流程：**可视化开发 → schema JSON → IM → OpenSCP 构建引擎 → .package**。
本文暂将 IM 作为用户指定的中间表示名称，不替项目定案其缩写、格式或现有接口。
Vue Flow 承担可视化装配；地图编辑文档应能脱离 Vue 和 Three.js 被读取、验证、编译。

需要支持三类作品：

1. 编辑原始地图：元信息、展示图、城市与伟工站点、地形和资源。
2. 将已有区域制作成单城市的全地图版本：入口、站点屏蔽、坐标映射、模拟边界与资源补充。
3. 生成新地图：例如用柏林噪声（Perlin noise）节点产生高度场，再装配完整区域资源。

## 预览期间应同步保存的信息

- 每项资源的源包指纹、完整 TGI、字段路径、解码格式、来源证据和已知缺失。
- 完整区域源场、独立城市源场、原始 tile 层级布局和头部；保留未识别字段/资源。
- 世界原点、轴顺序、单位、采样间距、尺寸、水位、高度编码和可见/可玩/模拟范围。
- 城市及伟工站点的稳定 ID、模板引用、位置、交通/资源元信息与本地化引用。
- 图片的语义用途、实际消费 UI、依赖资源、尺寸/格式；不以外观相似认定同源。
- 各字段是否仅供 UI 展示、影响模拟、属于派生数据或暂为预览近似。

`Region3DData` 是裁剪、降采样后的显示 DTO，**不能作为无损编辑源文档**。
GPU 网格、Three 对象、Vue 响应式状态和 base64 预览 PNG 不应成为构建引擎输入的唯一来源。
预览和构建应消费同一套已求值数据，预览允许降采样但不得覆盖源精度。

## 候选 Flow 节点边界

以下是待验证的设计草案，尚非稳定节点 API。

| 节点 | 输入 → 输出 | 关键约束 |
| --- | --- | --- |
| 导入区域 | 源包/TGI → RegionSource | 保留原始资源与引用闭包、解析诊断 |
| 区域元信息 | 区域 + 本地化文字 → RegionMetadata | 名称、介绍、启用信息和实际站点列表一致 |
| 展示图 | 图像/渲染结果 + 用途 → PresentationAssets | 示意图、封面、加载图分开；用途绑定待验证 |
| 城市/伟工站点集合 | 站点列表 + 增删/屏蔽操作 → SiteSet | UI 隐藏、禁止认领、删除模拟实体不是同一操作 |
| 城市说明与评分 | 站点 + 文字/资源评分/交通标志 → SiteMetadata | UI 评分不能替代真实资源量或道路连接 |
| 坐标映射 | 源/目标坐标框架 + 变换 → SpatialMapping | 可逆、显式单位；统一作用于地形/道路/资源/站点 |
| 高度编辑 | 完整源高度场 + 笔刷/导入 → HeightField | 保持精度、范围与城市独立高度场处理策略 |
| Perlin/fBm 生成 | seed/频率/振幅/尺度/八度 → HeightField | 算法版本固定，世界坐标采样，可重复生成 |
| 生态/资源画刷 | 目标字段 + 栅格/笔刷 + transform/混合模式 → ResourceFields | 无数据与资源量为零须区分；量纲、覆盖范围可验证 |
| 道路网络 | 路径 + 类型/材质/连接 → Network | 根据真实 PathEntry 构建；不能由 UI 标志伪造交通可达 |
| 全区域城市变换 | Region + 保留入口 + 各空间字段 → 候选全图 City | 依赖模拟/工具/相机/寻路边界能力验证，不默认可执行 |
| 区域装配 | 元信息/站点/高度/资源/网络/展示图 → MapDocument | 跨节点引用与 ID 完整性校验 |
| 预览 | MapDocument → 只读预览 | 源数据与近似显示可区分 |
| 构建 | MapDocument → IM → PackagePlan → .package | 资源冲突、版本、依赖、重读校验和游戏验收 |

节点端口应有数据类型，而非任意 JSON 互接。要求检测环路、缺失输入、TGI 冲突和引用悬空。
Vue Flow 的节点坐标、折叠状态等编辑器布局应与影响构建结果的参数分开。

## 屏蔽城市与添加区域

先用覆盖现有地图的最小试验验证，不能仅删除预览中的一个黄色框：

1. 对照模板 `boxes`、`map.cities`、地块表与注册表，确定站点列表的权威来源。
2. 分别实验不显示、不允许认领、移除站点；追踪旧存档兼容性与邻城/交通引用。
3. 添加城市站点与添加全新区域模板为两种操作：后者还涉及区域注册、唯一键、图片、
   全部场资源、城市启动数据及游戏加载顺序。
4. “城市数/伟工数”在编辑文档中优先从有效站点集合导出；若游戏还有冗余统计字段，
   编译时同步，禁止列表与 UI 数量矛盾。

## 全地图城市：必须验证的假设

用户此前观察：可玩区域内外高度数据不同、区域外缺关键资源、需要坐标对齐。
将这些记为**验收问题**，不把现象直接升级为引擎结论。

- 城市局部坐标与区域世界坐标可能存在原点变换；Three 又采用 Y-up。
  这不等于城市边界外不存在连续世界坐标。用同一组道路/地形锚点验证双向变换与轴方向。
- 区域高度 tile 与城市高度资源的确分开；需要验证进入城市后的采样、覆盖、分辨率和整平。
- 区域外关键矿藏缺失不能从 ED 推断。核对实际 typed map 范围、初始化流程和默认值；
  添加画刷也不意味着游戏已扩大模拟地图。
- 隐藏其他入口不能自动关闭其他城市实体或消除依赖；保留城市的模板、出生位置、
  认领信息、边界、相机、工具裁剪、寻路、代理和存档必须成套验证。
- 扩大渲染/可见范围不等于扩大模拟范围。全图方案可能还需要规则/脚本修改；
  若不能仅通过 .package 数据覆盖实现，构建器必须报告能力缺口，不能生成“成功”假象。

试验顺序：单入口但原边界 → 验证坐标与地形合并 → 分别扩大各模拟字段/边界 →
补资源并验证实际开采/抽水/风力 → 建路和寻路 → 保存/重载 → 大地图性能与兼容性。

## 新地图生成与 341 张 tile

**可以设计 Perlin 噪声节点**；高度场输出已存在可复用的打包路径，但新区域能否独立
进入游戏仍依赖模板、城市初始化和资源注册等未闭合链路。

341 是 `256+64+16+4+1` 的五级金字塔，不是 341 张同级图的平铺。
最细层 16×16 个 256² tile 拼成 4096² 全场；粗层从全场逐级降采样生成。
应先在统一世界坐标下生成完整高度场，再分块并重建金字塔，不能为每块独立随机采样。

`region_write.rs` 已有 `read_region_field`、`solve_f0_pyramid`、`build_heightmap_overlay`，
以及合成/真实区域 round-trip 测试定义。已有能力是高度场 overlay，不能称为完整地图编译器。
新生成场必须保留或显式分配 tile 拓扑/TGI，不能从全平/高对称新高度图的内容反推层级身份。

噪声参数至少包括 seed、算法版本、尺度/频率、振幅、八度、lacunarity、persistence、
高度偏置、水位和输出尺寸。规定量化/越界策略，计算 `raw=(z+1024)*32` 前检查 u16 范围。
坡度、陆地连通性、城市选址/整平、河道及生态资源分布是后续独立节点，不能等同随机高度。

## JSON 与重建路线

采用“JSON 文档 + 可校验的二进制附件”的候选形式。高度场等大数组不必展开成数百万
JSON 数字；可引用 u16-LE、无损 PNG 或具备明确格式的块资源，附长度与内容哈希。
也可以定义内嵌编码，但不能依赖未随项目保存的临时文件或本机绝对路径。

建议分开：

- `graph`：节点/边/参数/算法版本、显式输入；`editor`：节点 UI 布局。
- `document`：稳定区域/站点 ID、完整元信息、坐标框架、数据场、网络与展示资产。
- `assets`：相对路径或内容寻址、编码、尺寸、哈希、source TGI、依赖。
- `source`：基础包版本与指纹、未知资源保留策略、局部覆盖或完整新地图构建模式。
- IM：归一化数值类型、解析后的资源引用、空间变换与明确的输出资源操作；
  类型、哈希算法、ID 分配策略待结合项目构建引擎定案。

重建按两条轨道验收：

1. **无编辑 round-trip**：导入 package → 文档 JSON/附件 → IM → overlay/package →
   重读，比较高度场、原始 tile 身份/头、字段、引用和未知数据；检查未编辑资源保真。
2. **受控编辑**：每次只改名称、介绍、一个展示图、一个站点、一个高度/资源笔刷，
   检查最小输出差异，再在游戏中验证选择、进入、保存和重载。

容器压缩、条目排序等允许变化时应明确“语义等价”而非宣称整个 .package 字节相同。
未知资源采取原字节保留；不能通过只序列化当前已识别字段来冒充完整无损重建。
UI 评分与实际资源字段可建立验证/推导关系，但未证明算法前须分别保存。

## 预览完成后的研究优先级

1. 补齐区域/城市所有元信息字段、两类展示图与实际 UI 消费链的资源清单。
2. 建立不修改数据的完整地图文档导入与 round-trip 基线；以此确定节点粒度和 IM。
3. 最小元信息/图片覆盖，验证游戏载入；再实现站点屏蔽与新增。
4. 高度编辑/Perlin 输出复用既有金字塔 writer，补齐生态资源和城市初始化。
5. 全地图城市独立实验，先验证模拟能力，不与普通地图编辑共享未经验证的默认假设。

当前缺口必须保留在任务记录中：真实煤油矿分布、EcoPathSet、原版树种/impostor，以及
完整地图重建与全地图城市仍未实现。后续继续预览时，应沿上述资源账本积累证据。

### 坐标与森林资源账本补充

泰坦峡谷镜像问题确认来自预览坐标转换：游戏 `(x,y,z)` 必须映射为
Three `(x,z,-y)`，不能仅交换 Y/Z。JSON/IM 应保留游戏原坐标和原始栅格行序；
显示转换仅在场景边界执行一次，编辑拾取须使用逆变换。站点 1029（定居者之地）
的非对称道路/河湾可作往返验证锚点，不能用对称地形验证手性。

原版森林模型链及四个已解码 RW4 的 TGI/纹理尺寸见 `map-layer-preview.md`。
未来植被节点需分别保留模型引用、环境/季节配置、密度场、分布采样参数；
当前预览树木的实例列表不能作为原版森林数据的无损替代。
