## 已经闭合的行为

1. **水和电是实际本地消费。** 规则 `0xd54f8b18` 对水 `0x9e3c3dfa` 观测到 `3024 → 2016`，净变化 `-1008`；规则 `0xd51cb94c` 对电 `0x8e8b4e10` 观测到 `28485 → 18990`，净变化 `-9495`。这些操作覆盖六个工厂，属于真实 bin before/after 变化。
2. **劳工主要是状态维护，偶尔出现净减少。** `TotalWorkers (0x1fd156b6)` 多数操作是 `input=1/output=1, delta=0`；少数规则出现 `-1`、`-2`、`-3`，说明存在离岗/状态迁移写入，但本轮不足以把它解释成具体市民的上下班路径。
3. **原油和原矿在本轮主要表现为补货/填充。** 原油 `0xbf75dc04` 和原矿 `0x96cf3b07` 的正向写入把库存补到 `60000`，典型由规则 `0xf2c1a0fd`、`0xed7cb6ea`、`0xf776e9fa`、`0xbcfc4767` 执行。规则 `0x645b10e4` 对两者使用 `input=3/output=3, delta=0`，是检查或配额推进，不能当作消费。
4. **处理器没有在这段本地消费窗口中发生直接扣减。** 工业处理器 `0xbee1c73e` 的定向 effect 记录只看到它自身保持不变，同时 `0x2cfe923b`（静态符号确认的 Electronics capacity）发生容量操作；`unit-consumption` 汇总没有 `0xbee1c73e` 的非零净变化。当前更支持“处理器属于无人机/总部链条或容量追踪路径”，不支持“工厂在本窗口直接消耗处理器”。

## 关键的隐藏双缓冲链

规则 `0x6001451b` 在六个工厂上反复同时扣减两个 60000 容量的未知资源：`0x415586b3` 与 `0xd3c17458`。例如 slot 561 在 tick 50940 发生 `5350` 与 `9700` 的同步扣减；slot 418 在 tick 51026 发生 `4300` 与 `19450` 的同步扣减。上一轮的 effect 捕获还显示规则 `0xded740d2` 会把这两个资源等量写回，因此它们构成“清空/再填充”的双缓冲或转运对。

这两个 ID 尚未在安装版 UI 符号中找到正式名称，不能直接称为“原油”“原矿”或“Omega”。不过它们与 `0x6001451b/0xded740d2` 成对出现、数值容量一致、且跨六个工厂周期性运行，已经可以作为 Omega 工厂生产链的高价值追踪点。

## 当前对生产链的判断

目前可以确认的顺序是：工厂先维护劳工和公用事业条件；原油/原矿库存通过补货规则维持；条件检查通过后，隐藏的双缓冲资源对会被 `0x6001451b` 消耗，再由另一条规则写回；处理器路径在本轮只表现为容量追踪。这个链条与 OmegaCo 的“原油 + 原矿 → Omega”静态设计说明相符，但尚不足以给隐藏资源命名为 Omega 成品，也不足以算出每小时产量。

下一步应只针对 `0x415586b3`、`0xd3c17458`、`0x11a2434e`、`0x8e25d7fb`、`0xf40144d9`、`0xce415e6a` 做短时单资源捕获，并同步记录相邻的原油/原矿库存；若能证明某一对资源在写回后进入运输或 Omega 消费规则，才能闭合产品语义。
