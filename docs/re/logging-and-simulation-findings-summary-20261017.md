# 日志与模拟诊断阶段总结报告

日期：2026-10-17。范围：截至本日报告和已归档证据，不包含新的运行时采集。

## 一、总体结论

目前已经能够观察 UI 通信、引擎文本、package 加载、部分规则执行及资源数量变化；交通研究也已从不确定的对象扫描推进到管理器归属和速度字段验证。我们已经具备对具体问题做定向诊断的基础，但尚未建立覆盖全城、无丢失、统一时间轴的完整模拟日志系统。

必须区分三类证据：**原生输出和调用探针记录、静态代码语义匹配、外部只读内存快照**。它们相互补充，但不能互相替代。尤其是车辆速度观察，并不是游戏已经主动输出逐车运动日志。

主要实机结论针对同一离线零售 EXE，SHA-256：

`2b0aff527baa3aa536aca6c68332c208d1dbd904695f0f985d17d56b128d48ab`

地址、对象指针和布局均受版本及进程生命周期限制。本报告中的次数来自不同历史窗口，不合并为一个“总覆盖量”。

## 二、已经确认的能力

| 层次 | 已确认结果 | 不能据此推出的结论 |
|---|---|---|
| UI 桥接与页面控制台 | 可以观察请求、返回、事件和页面控制台输出 | 不能代表全部引擎日志；规则 UI 事件不等于规则执行成功 |
| 引擎文本 | 已取得 EA::Trace 链路中的完整文本，包含 Config 和 UpdateManager | 不能恢复未生成、被前置过滤或编译移除的日志 |
| package 加载 | 可以区分打开、注册、实际选中资源及创建 Record；部分规则已关联到最终返回对象的来源包 | 包注册成功不等于资源被采用，更不等于 Mod 行为正确 |
| 规则身份和定义 | 已关联运行态索引、规则索引和规则 ID；采集的全局定义与离线 AEB 内容一致 | 索引不能跨 game 对象直接沿用；规则 ID 不等于可读名称 |
| 规则条件与资源更新 | 已观察允许/拒绝检查，以及全局和单位本地资源的执行前后值 | 条件允许不等于执行；局部原生返回成功不等于整个玩法成功 |

| 交通模拟 | 已找到有车辆记录的管理器，并观察归属车辆对象的当前速度变化 | 尚无完整轨迹、道路段、稳定身份或全城车辆统计 |

## 三、关键实测结果

### 1. 引擎文本：链路已通，覆盖范围有限

两次各 35 秒的启动观察中，基线记录 253 条；启用 Server 观察后的窗口记录 384 条，其中 **131 条是完整引擎文本**，包括 Config 119 条、UpdateManager 12 条。对应窗口 errors/dropped 均为 0，采集结束已 detach。

格式化、Server 和 Reporter 是同一输出的不同阶段，不能把各阶段命中相加当作独立游戏动作。`LogGlobalRule` 写入二进制 delta，不是普通引擎文本；ArgScript 的 `output`/`trace` 也不能一概当作 EA::Trace 输出。

### 2. package 与规则来源：已有实际对象关联

最小单 TGI overlay 实验显示：放在用户 Packages 目录时，包虽注册成功，目标仍取自 App；放在 SimCityData 时，目标实际取自测试包。这证明安装位置和实际选择链必须验证，不能仅凭文件名或“注册成功”承诺覆盖。

规则来源采集进一步将一次完整的 OpenRecord → 工厂创建 → ResourceManager 最终返回链，与随后城市使用的规则集对象关联，确认目标来自 **SimCity-Scripts_287520926.package**。同窗口也加载了其他版本，因此不能用首次或最后一次同 TGI 加载替代对象关联。

质量限制：进城窗口记录 475 条、丢弃 186 条；独立校验得到 21 条完整来源链及 1 个不完整事件组。完整目标链可支持对应来源结论，整个窗口不能称为无损。后续队列修复经过模拟突发验证，尚未重新进行实机冷启动验收。

### 3. 规则定义、条件和资源效果：已有定向闭环

| 实验 | 实测结果 | 证据范围 |
|---|---|---|
| 全局规则定义 | 15 秒采集 59 条定义记录，59/59 与离线 AEB 字段相符 | 是采样记录数，不是 59 种不同规则；基础定义不总是最终动态操作量 |
| 规则条件 | 10 秒采集 410 次检查：允许 243、输入不足 83、容量限制 7、上界限制 76、控制标志 1 | 410/410 对拍通过；允许与实际执行仍须区分 |
| 全局资源生产 | 15 秒内 7 次更新，目标资源数量 2→9，每次 +1，容量 24 | 7/7 前后快照核验通过 |
| 单位本地生产 | 15 秒内捕获 1 次更新，数量 586→864，applyCount=278，差值 +278 | 证明一个目标单位本地更新，不代表所有生产活动 |
| 单位本地消费 | 15 秒内 52 条完整更新，目标消费资源出现 104→103→102，每次 −1 | 目标规则还包含生产操作；不是只有消费的规则 |

上述定向窗口各自报告 errors/dropped/incompleteRequests 为 0。额外的 5 秒多目标消费采集达到 100 条上限，覆盖 57 个单位指针、80 个单位/规则组合，同时主动丢弃 13,873 次超限事件。这说明定向样本少不代表城市活动少，也说明扩大目标后必须保留容量与丢弃指标。

“单位”尚未可靠映射为具体建筑、车辆或行人；slot 和指针不构成跨生命周期身份。资源更新函数还可能在写入后返回失败，所核对局部路径没有回滚，因此不能把失败简单解释为“资源未改变”。

当前规则资源没有包含可读名称，运行对象也不保留可供直接读取的名称。后续需要基于源码或构建产物建立外部符号关联，明确名称不是引擎直接输出。

### 4. 交通：已观察速度变化，未形成全城运动日志

最新结果来自外部 `ReadProcessMemory` 只读采样及零售反汇编与开发版语义对照，没有安装 hook 或主动调用游戏函数。

- 已通过管理器哈希表、分桶关系和车辆 vtable 校验，建立车辆对象的管理器归属。
- `UpdateAgentInfo` 的静态分支和数据流支持当前速度、目标速度、加速、制动、停止时间等字段语义；速度单位尚未确认。
- 连续 11 次表遍历的节点样本数为 **97、87、116、110、103、99、99、82、69、70、70**。
- 相邻快照按交易索引和对象地址配对，共得到 **506 次当前速度数值变化**，未报告读取或节点校验错误。
- `SimulateAgents` 仍为静态控制流匹配的入口候选，尚未用执行观察确认其调用。

这些数据支持“所读取的管理器所属车辆状态随时间变化”。**506 是变化次数，不是独立车辆数；每次遍历数量也不是全城车辆总数。** 遍历期间表可能变化，地址和交易索引可能复用；尚未获得 stamp/tick、世界坐标、道路段及完整的同步暂停—运行—暂停对照。

## 四、必须保留的历史纠正

1. 先前将零命中解释为菜单状态没有依据，已撤回。用户反馈和截图不能被一次阴性扫描否定。
2. “车辆类型没有 RTTI”是扫描器遗漏结构体标记 `.?AU` 的错误；另外一次 VA/RVA 混用也使相关阴性结果失效。
3. 旧扫描条件 `Protect & 4` 没有覆盖所有可写页。管理器实际位于 `PAGE_EXECUTE_READWRITE (0x40)` 页，这是此前管理器零命中的直接原因。
4. 用户后来说明早期采样时游戏暂停；旧候选不变化本身仍不足以证明暂停，也不能排除闲置或失效对象。恢复运行后的新采样才补充了变化证据。
5. 旧 package writer 的多条目索引标记问题已另行定位并修复；单 TGI 成功实验不能替旧实现证明多条包兼容性。

## 五、工作台落地与采集质量

专题记录已确认诊断工作台支持 JSONL 导入、筛选、请求/返回配对、主机标记、导出，以及规则相关记录展示；后续增加了 delta v4 外层导入和 `status.json` 质量信息关联。此处总结已验收能力，不将所有研究采集器都视作已完成统一产品接入。

历史导入验证包括 142,566 条 UI 记录、70,363 组请求/返回配对和 1,324 条 UnitRuleUIEvent。两个 delta 副本分别有 45 条和 4,265 条记录，后者 tick 全为 0，不能拿记录数直接表示模拟推进次数。

质量解释应始终遵守：

- `dropped=0` 只说明所配置通道未报告容量丢弃，不包含主动筛选、窗口外事件或未覆盖入口。
- 无读取错误不代表快照原子，也不代表对象身份稳定。
- `status.json` 的记录数一致不证明文件来源相同；现有用户选择关联未做 trace 哈希身份绑定。
- 主机 marker 是诊断注释，不是引擎执行证据；UI 时间与 delta tick 缺少关联键时不能拼出因果链。
- 原生 hook 采集会临时修改入口指令，并可能带来开销；不能与本轮交通外部只读采样统称为“零侵入”。

## 六、后续优先事项

1. **补齐交通时间与身份**：恢复 tick、稳定生命周期标识、位置与道路段，完成同步暂停对照，使速度观察能够发展为可靠轨迹。
2. **强化证据完整性**：为 trace/status 建立哈希绑定；对来源采集队列修复补做实机验收；保留筛选、丢弃、截断及非原子状态。
3. **补充可读语义**：建立规则/资源名称侧表和单位类型映射，保留歧义及来源摘要。
4. **统一定向诊断体验**：以选定对象、规则和短窗口为基础接入研究能力，再评估扩大覆盖范围所需的性能与队列预算。
