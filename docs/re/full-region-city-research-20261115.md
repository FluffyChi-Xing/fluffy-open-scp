# 全区域单城：研究目标、证据与第一轮实验

2026-11-15。这里的“全地图”指地图工作台显示的**整个原版可见区域**：只有一个可认领、可存储的城市槽；在原城市边界之外，原版道路、分区、建筑、服务和资源模拟都属于该城市。仍保留有限的外缘用于防止越界。海域和陡坡维持原有建造规则。伟工不是城市槽，先保留为单独的兼容性验收项。截图标注的 Export overlay 是地形编辑入口，本轮沿用该地图的坐标与数据，未修改 UI，也不把现有高度 overlay 当作城市扩容能力。

用户指定的主实验已改为[爱华特湾 1031](#爱华特湾与-orion-xy-实验)。后文三一岬、白水谷和 Gallia 仅保留为历史证据和计算对照。

## 旧 BOC 包究竟改了什么

对照用当前离线安装的同修订号 `SimCity-Scripts_272391411.package`，它和历史安装根下的同名包整包哈希一致。先验哈希，再用仓库 `pkg_diff` 解压逐 TGI 比较、`prop_diff` 逐属性解码：

| 样本 | SHA-256 |
| --- | --- |
| 安装目录同修订对照 | `70AF893554E88E8A5E4862C87B6DE6CEF3823FEF6FF0594D0F7AD66FBB7663DB` |
| 指定 BOC 普通脚本包 | `77DA81E21A63C816E9ABAB9BE36DC39B426A71C17D4883BAFAFECB2974FA0228` |
| 指定 BOC OverPlop 脚本包 | `D5B6B87080767713BA90D40E406F064A602306462EA449B5F092743024970189` |
| Universal Street 脚本包 | `CB7A3F8A0CA78BED07FAACD82E0076CD794303DBA227D39F548CA6B21BFB50EE` |

- 三包各 10,155 个 TGI，集合相同。对照 → 普通版有 **194** 个变化：`40E0C000` 45、`40E0C400` 106、`48E0C000` 43。普通 → OverPlop 有 **42** 个变化：这 42 个资源分别位于 `40E0C000`（39）、`40E0C700`（1）、`48E0C000`（2）。两轮全是 Property，没有改到 `40800200:622B9CD7` SimProperties，也没有增删 TGI。旧报告的相同核心载荷和 29 个成本字段只描述之前取样的部分。
- 106 个变化的 PathEntry 全部改了 `0x0D6498E8`。开发版 `GB/cEcoGameScripts/AddBaseEntitiesFromGroupIDs.c:535–573` 读取为 `pathFilters`，按 key 的 instance 查过滤器。因此这是**路径过滤器成员关系**的实证。白水谷已对齐的原版道路 entry `04F90CCD` 在 BOC 中增加过滤器 `587D51B9`，另移除五个空数组。该成员在哪个建造入口被接受、产生什么实际交通效果，仍需追消费者和实机验证。
- OverPlop 的 39 个 Unit 行改变 `0x0CC8BE20`；例如 `0403377D` 新增该字段值 400，`0x0CC8BE51` 由 16 变 400。不把数值猜成“全局放置上限”。独立 Universal Street 只替换 `00B1B104:40E0C400:6BD045FC`，改引用、路径过滤器和多组路径参数；它也没有调整网格大小。独立 `1_bRangeRemovals` 含 29 个 Property，`1_aaWHATHAVEIDONE` 含 4 个 Property 和 4 个 `2F4E681B`。本轮未执行目录内 BAT。
- [Project Orion 的作者发布页](https://community.simtropolis.com/files/file/29650-project-orion-3k-extended-boundary/) 将区域道路等列为依赖。另有作者自报 [macOS 4096×4096 原生模拟原型](https://www.reddit.com/r/SimCity/comments/1w3mrkx/13_years_later_simcity_2013_can_run_fully/)，并说明交通和性能仍有限；这是独立线索，本轮没拿到可核对的 Windows 产物。此处 BOC 字段结论不外推到 Orion 的包。

## 地图边界、尺寸与状态必须一起闭合

指定 PDB 目录的松散 `SimCity.c` 搜索命中部分声明和反编译错误指令；函数体使用同一 `new-cource` 下的符号化 `SimCity2013-source-tree/src` 对照。以下地址为开发版虚拟地址，零售地址仅引用已经对拍过的记录。

1. `GB/cEcoGame/InitGame.c:115,164–174`（VA `0x60BDC0`）：`0x07E0AC05` → PlayArea；每格宽度 = PlayArea 宽度 / MapBounds。两份安装脚本 `272391411`、`287520926` 的 `00B1B104:40800200:622B9CD7` 都实读到 XYZ −1024..1024、XY 网格 [128,128]。这证明包中确有这些值；当前会话实际选用哪个脚本叠加仍需验证。开发版 `GB/cEcoGameScripts/Init.c:277–301` 优先读 `0x0D4AE7FE`；回退源码十进制 141321871 对应 **`0x086C668F`**，旧文档十六进制有误。
2. `SC/cTerrainMapSet/WorldToEco.c:31–45` 使用共享 `smScalars.mFlatScale` 和给定 ecoSize 来映射以零为中心的正方形；高侧夹索引、低侧不夹。对非居中 PlayArea，增加一个半幅不能让该入口与 EcoGame 格子同址。首个扩容样本保持原点和四边对称；整区若保留偏心槽原点，需将有效 bounds 变换成城市局部并确认所有消费者支持非对称域，或在新模板选用区域中心并按帧转换 bootstrap，择一验证。检查 `SetFlatScale` 的所有消费者再决定改参数还是将采样改为实例范围；它不是单城私有开关。
3. `GB/cEcoMap/FillFromProps.c:29–31` 用 MapBounds 建立栅格；`GB/cEcoMap/Read.c:24–31` 比较序列化单元数与实际 X×Y，失败返回 0；`GB/cEcoGame/Read.c:167–208` 先调用 InitGame，再按 typed map ID 反序列化已注册地图，失败进入读档错误分支。因此只改 MapBounds 再喂旧 128² 城市基线，开发版这条路径无法读过。零售优先对拍此路径，不能把“改一个属性”当作地图写入方案。
4. `SC/IsSegmentInPlayArea.c:30–40`、`SC/cZoningGame/StartGame.c:72` 都消费 PlayArea；零售 Glide 已定位的 [0.996 夹取路径](map-consumers-ui-bridge-camera.md#2026-11-12-零售-glide-对拍) 也消费 PlayArea。扩大后仍需验普通道路、城界连接点、分区网格与各相机输入。区域高速和 Great Works 的接入不能假定会随边界迁移。

## 实验顺序与停止条件

1. **S0：只做单槽。** 先在三一岬三城基线留一个城市，使用独立实验模板。校验 CityList 五数组、离线模板的 `map.cities` / `boxes`、`46066280/81` bootstrap Key/UID 配对及元数据；保留 site 0 和保留槽原点，审计被屏蔽城市的道路/伟工引用。先读离线 `RegionTemplates` 响应，再看认领、首次保存及重载。任一层还有多个城市就不继续扩大。
2. **R0：不改尺寸，只改一个已确认城市的煤基线。** Gallia 1026 原煤为零，是对照样本。在建造合规且远离水体的固定世界锚点下写一个足以覆盖采集范围的小煤斑；用原版煤矿比较目标区与同地形零煤对照。验证读入、显示、产出、耗减、重载，定位零售初始化是否采用 EP1 状态。先做零改动逐字节回读门槛；当前读器不是可部署写入器。
3. **B1：只扩一个小窗口并保留 16 m/格。** 原点固定，可从 2048/128² → **4096/256²**；先枚举零售实际加载的 SimProperties、地图序列化、城市高度和材质采样约束。白水谷 1027 已有局部点 `(1038.048,−544.2923)` → 区域 `(2062.048,215.7077)` 的原版样条和 F0 接缝，可做坐标对照；4096 对称域下按半开格概念落 `(192,93)`，原有 128² 格从目标 `(64,64)` 开始，保持同一米制格宽。用四边的原版道路、RCI、服务验证，最后将 R0 探针移到旧盒外。若原版道路能画但分区或保存失败，先定位首个失败消费者。
4. **B2：8.192 km → Gallia 16.384 km。** 保持 16 m 格意味着 512² 和 1024²，分别为原城每层格数的 16 倍和 64 倍。按开发版 i32 内存格估算，Gallia 单层约 4 MiB；如果沿 1026 的 33 层规模，地图数组本身约 132 MiB，还没算纹理、道路、代理或额外状态，也不等于压缩档大小。对称域不能随意沿用偏心槽，例如 Gallia 1040 槽原点 `(1744,3328)` 使整区局部目标范围成为 `[-9936,6448] × [-11520,4864]`，不等于 `±8192`。把区域绝对范围转为局部再验四角，或在独立模板重定原点并转换城市 path/unit/lot；site 0 的区域数据继续留在区域帧。每级记录 tick 和内存，单独验证伟工与区域货运。

构建前的硬闸门：UID 唯一且各表对齐、site 0 未丢失、目标坐标四边与分辨率一致、每张模拟图格数与校验和一致、path/unit/lot 不重复平移、所有基线和引用重开包可追溯。部署验证沿项目台账和存档隔离规则执行，用户冷启动看主菜单，异常即停止。本轮未构建或部署地图包、未启动游戏。

复现材料：`tmp/citybox-unlock/{boc-base,overplop}-{tgi,fields}.log`；先用 `pkg_diff` 得到变更 TGI，再把三段十六进制分列传给 `prop_diff`。Gallia 原包条目用 `pkg_extract`、gzip 解压、`cargo run --offline -p probes --example region_state_probe -- <bin> <out.json>` 复核。安装的 RT0、EP1 基线哈希见[白水谷跨界对拍](region-city-coordinate-sync-and-placement-alignment.md#2026-11-12-白水谷原包跨界对拍)。REA 在本会话未注册，CLI 诊断因 npm DNS 失败；以上证据来自现有反编译和仓库实包探针。

## 爱华特湾与 Orion XY 实验

用户确认爱华特湾目前没有该区域的存档。选用 `EdgeWaterBay/A0B60DDE` 的 1031 槽，环境组 `81CED36F`、原点 `(-2496,1472)`。原版有 7 城和 1 个伟工位，可见区域是 `[-8192,8192]²`。1031 是七城中距离区域中心最近的原版槽，煤层全零。其 `08068AED:CCDFF91D:021BDA2F` 原始 gzip 条目 SHA-256 为 `0AC5C2608A14DF296DE3B790F06E187EAC20C614A9C000D1FA63AE9EE45C7D3A`，解出 v17、34 张地图、215 条曲线。保留原槽原点时，整区对应局部 X `[-5696,10688]`、Y `[-9664,6720]`。

指定 Orion XY 包的 SHA-256 为 `8FFF09442287A0718BF988DF9D77C9EF56BAB822F1BE3E677CC77124BB64ED17`。全包只有 `00B1B104:40800200:622B9CD7` 一条 6352 字节的 SimProperties，内置脚本修订为 `287520926`。安装目录的同修订脚本包 SHA-256 为 `77DDCED4A23A818673E44C19649732390D8771BC5A1434583032E5841BAEDD04`。解压后逐字节对拍，只有 11 个字节不同。8 个字节属于 `0x07E0AC05` 四个变化的浮点分量，余下 3 个为字符串中的 CR 字节由 `0D` 变 `00`。TGI 字段对拍见 `tmp/citybox-unlock/orion-vs-287520926.log`。

| 条目 | 零售 287520926 | 指定 Orion XY |
| --- | --- | --- |
| PlayArea XY | 两轴 `[-1024,1024]` | 两轴 `[-1024,3072]` |
| PlayArea Z | `[-1024,1024]` | `[-2048,2048]` |
| MapBounds | 128×128 | 128×128 |
| 按 InitGame 公式推得的 XY 格宽 | 16 m | 32 m |

这个包确实改了逻辑边界，对应 **4096×4096 米的偏心方框**。它替换共享 SimProperties，因此只靠安装包本身无法将它限定到爱华特湾。按现有反编译推算，若该覆盖生效，原版 128² bootstrap 仍能满足格数要求，但 EcoGame 的 `mPlayCell` 会变成 32 m，独立的地形采样配置仍是原值。例如城市局部 `(0,0)` 在新 PlayArea 的 32 m 格中为 `(32,32)`，而原 `WorldToEco` 为 `(64,64)`。这是坐标映射差异的可复现静态预测，实际图层和工具行为待冷启动对拍。[Orion 作者发布页](https://community.simtropolis.com/files/file/29650-project-orion-3k-extended-boundary/) 另列区域道路等依赖。

后续按爱华特湾的同一槽位验收。单槽阶段同步 CityList、模板、boxes 和 bootstrap 绑定，只保留 1031 与区域 site 0。Orion 对照阶段可用 path 30 的原版样条端点 `(-1008,1080.9099)` 检查 +Y 方向旧盒外点，区域坐标为 `(-3504,2552.9099)`。真正扩域阶段从对称 4096 m 和 256² 开始检验原有 16 m 格宽，再处理全区域的非对称局部范围。

煤斑对照包为 `tmp/citybox-unlock/000_OpenSCP_Map_EdgeWaterBay_1031_CoalControl.package`，SHA-256 为 `16499DDCBA4CE2F3DDCE16CE7434B4CD173E8CB4C8D18E408593BB479170720D`。它保留原尺寸和原始 v17 载荷格式，改变煤层 `D779C976` 的 9×9 格与格值总和。中心格 `(51,57)` 对应局部 `(-200,-104)`、区域 `(-2696,1368)`。每格 32768，合计 2654208。重开输出包并解压，校验只含目标 TGI，煤层 81 个目标格逐格匹配，其余载荷在还原原煤记录后与源包解压字节一致。该点的格网和原地形样本已核对，具体矿井落点及产出仍需游戏验证。探针命令如下。

```powershell
cargo run --offline -p probes --example region_coal_control -- <SimCityDataEP1.package> CCDFF91D 021BDA2F 81CED36F 51 57 <out.package>
```

当前安装目录已有多个 `000_*.package`，历史台账记录其中有已实机验收的资产。爱华特湾没有存档只解决实验区域选择，现有存档和包集合仍按项目隔离规则处理。煤斑样本与 Orion 均留在工作区或原来源目录，游戏内结果待隔离环境验证。

### 嘉納谷煤斑实机验证

用户随后用原版煤矿实测。区外显示「這裡沒有煤礦」，煤斑上显示可采 196.6 吨。采矿厂运作后显示 0.8 吨/天，库存 0.8/20 吨。重新核对构建件和部署件 SHA-256 后，只读解码 1031 的 `state_file_486_1794675778139.egb`（SHA-256 `6B22C2CC2F509A53B48FD0E8D60909AB62AFB0E546050075FF62D4C4A77CD6D7`）。与首次存档逐格相比，81 个目标格全都减少，无格增加，煤层总和从 2654208 降到 2651208，减少 3000 个原始单位。原尺寸下的识别、生产、耗减和写盘已证实。冷重载持久性和盒外开采仍待验证。
