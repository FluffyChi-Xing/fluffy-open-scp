## 可复现的拥挤规则异常

社区大学的教育 bundle `40E0C700:6C042366` 和大学的教育 bundle `40E0C700:3256C0A2` 都注册 `23E737BC`，并声明以下三个本地资源。失败边为 `23E737BC → 5FD624B3 → B322BAFD`。后者成功后进入学生释放链 `A4720F5A`，自身没有失败边。

| 资源 | ID | `B322BAFD` 的操作 |
| --- | --- | --- |
| OverCrowding | `14A99156` | 检查至少有 1，等量归还 |
| StudentStudyingE2 | `CF0B7832` | 输入取同一个本地 OverCrowding，输出 0 |
| StudentStudyingE3 | `CF0B7833` | 输入取同一个本地 OverCrowding，输出 0 |

两个版本的动态操作均为 `00 00 02 00 56 91 A9 14 00 00 03 00 56 91 A9 14`，分别写本地操作索引 2、3 的输入。287520926 中规则索引为 5299、记录偏移 `0xC0155`、动态操作偏移 `0x488E30`。281567759 中分别为 5282、`0xBF7C5`、`0x485E70`。两版的 min/maxApply 都为 1。相邻的 `A59ECECA` 也清理两个在学 bin，但它从各 bin 自身读取清理数量。

开发样本的 `GB::ApplyAmountsFromBins`（`0x64BA70`）在模式 0 下以来源 bin 的当前值替换目标操作的 `mInput`。`GB::TestBinRule`（`0x64C110`）对每项检查库存是否满足最低应用次数，`GB::BinRuleCount`（`0x64B990`）同样按各项可应用次数的最小值计算。按此推导，若 `OverCrowding=1`、E2 在学量为 0、E3 为 10，则这条释放入口无法通过 E2 的输入检查。若两档各有 10，则入口会从两档各扣 1。这是编译数据和引擎检查逻辑支持的条件性结果，尚无零售版实机触发轨迹来测发生频率或确认玩家可见症状。

## 补丁验收点

同一动态来源被用于两个分档扣减，符合复制粘贴失误的嫌疑。原意可能是只处理 E3，或从两档合计释放指定人数。确定方案前可在隔离城市分别测试只有 E3、两档混合和只有 E2 的情况，捕获上述三个 bin、`B322BAFD` 的检查结果以及 `A4720F5A` 的实际派发。现阶段没有修改脚本包或安装目录。
