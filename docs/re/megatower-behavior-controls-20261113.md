## 塔基与楼层的分工

- 普通塔基 Unit `61EFC000:D381A8C4` 的 `0AFE27CA` 指向模块类别 `24E44222`。菁英塔基 `61EFC000:8441115E` 对应 `259FFE38`。楼层菜单组为 `61F0C900`，其中 `0DB9FC63` 选塔类，`0975695F` 选模拟 Unit。例如普通住宅首层放置项 `79C39E71` 继承普通塔基，以 `07E0AD0A` 引入公寓 `93E3DB12` 与公共子单元 `50E18927`。菁英住宅首层 `C29D1DBB` 同样引用公寓 `2B0E9B85` 与 `50E18927`。
- 模拟 Unit 继承 `61EFC000:337D999E`，建筑配置继承 `61F0C000:337D999E`。所查住宅、商场、办公、观光及公园模块配置的 PathEntry 为 `40E0C400:03106C2E/418A18B1`，两条均为 Local + None。普通塔基配置明写 Global + First/Last 与 Local + None 两类路段，两种塔基 Unit 都有内部路径引用 `B940136F`。空中桥梁桥基是例外，显式有 Global + Last。菁英纯塔基配置的同一组路连列未见显式值，不能据普通塔基推定它的每条路段编码。
- 34 个模块都显式启用 `61EFC700:E678CDF8`。其事件槽 `08327D48` 引用 EP1 规则 `CC13B7D9`，全局资源 `05AFD67D` 的输入与输出均为 1。这个共享依赖属于楼层上下文，具体运行时注册与层间调度仍需实测。冠楼另有 `FB0C2774`，其中 `631A3D47` 同时引用本地、附近和全局资源。

## 住宅满员对照

用户观察到地面科潘配方达到 300／1100，普通塔 § 公寓可达到所观察的人口上限。已核验当前部署的 `000_OpenSCP_Commercial_Copan_Vacancy_Test_20261113.package` 和构建账本指向的 `.build/4bdedfb427009f7337a454bd32053621fda10de96d7f420b71310b50b656848e/packages/000_OpenSCP_asset.package`，两者 SHA-256 均为 `4d916230fc2ddd43ec9882042f93bcf4bfa782d834b85295ce937c9710f9bb66`，与 MANIFEST 的 GOLDEN-known-working 记录匹配。GOLDEN Unit `40E0C000:F1A4104F` 写入总人口 1100、W1 居民劳工 800、W1 居民消费者 300，带 `EE66978E/AB9A0A3E/9DEF44FB/5D5EF1FF`，初始 flags 是 49、22。通用建筑人口浮层读取 `TotalResidents.amount`。

两份基础游戏人口 bundle `40E0C700:AB9A0A3E`（科潘）与 `40E0C700:D4C30C02`（普通塔 § 公寓）在本次属性读回中逐字段一致。它们都把 `TotalResidents`、`TotalResidentWorkersW1`、`TotalResidentShoppersW1` 的容量分别绑到 `0A7917CB`、`0E33502E`、`0E335022`。普通塔 § 公寓在这三列填 1200、800、400，800 可确定是居民劳工容量。游戏内观察的 800 需要对应具体显示项，才能与科潘的 `TotalResidents` 比较。

| 填充路径 | 规则证据 |
|---|---|
| 科潘的渐进入住 | `EE66978E → 200D7C9C → 09BE9888 → 9B8566E9 → B0B6387A`。消费者支路消耗全局 `9FCD15EF`，为消费者和总居民各加 1。劳工支路消耗另一全局资源 `99DA4940` 及本地 `03812CB3`，为居民劳工和总居民各加 1。基础规则中的劳工丢失及释放也能补充 `99DA4940`。接收回家的劳工规则 `FA49BD3D` 同样消耗本地 `03812CB3`。 |
| 普通塔 § 公寓的填充 | `61EFC700:78A730CD` 将接收项 `BBAAD3D1` 绑定到 EP1 规则 `81AA8640`。后续 `1B2AF135 → 2188CA6B → A8076540 → F012362E → 1788982F` 更新空置状态和人口相关资源。`1788982F` 读取本地各 bin 的剩余容量，分别写入居民劳工、消费者、总居民及儿童等资源。这条路径的填充操作无需逐人消费科潘渐进规则的 `99DA4940`。普通塔 § 公寓也启用 `EE66978E`。 |

300 正好等于 GOLDEN 的 W1 消费者容量。若同一时刻读到 `TotalResidentShoppersW1=300`、`TotalResidentWorkersW1=0`，即可把问题定位到居民劳工支路，再核对本地 `03812CB3` 与全局 `99DA4940`。建筑自身的 180 个岗位与这两个居民 bin 是不同指标。本次仅验证了原版规则和成品配置，尚未读取出现 300／1100 时的运行时 bin。住宅满员课题应优先研究楼层入住和填充链，以及满员后的居民外出、回流和全局计数。

后续沿入住 sink 追到科潘也有直接填充链 `999F8484 → BBAAD3D1 → ED171D40 → 02065E35 → 7B5F28D2 → 337A4D2F`。`337A4D2F` 同样读取各人口 bin 的剩余容量。渐进入住资源的短缺、直接入住链未完成、或入住后流失都可能形成相同的总数，需要实测区分。

商业地标的 `megatower-residence-v1` 对拍包保留 1100／800／300 的容量和地面接入，采用原版 `78A730CD` 入住绑定、`EBFC1753` 容量与状态 bundle、原版 W1 单位分类键 `31D3307B`。排除竞争的旧绑定 `999F8484`，保留 GOLDEN 的其余住宅生活规则。办公叶子采用普通中科技楼层的 `1E16EDA9` 劳工接收与 `6A326F41` 生产规则，默认 400／200／100 岗、最低开工人数 1。配方以 SC5 Asset Packager `behavior_profiles.py:62–95,106–137` 的原版记录选择、应用与回读方式为依据。办公和住宅候选均通过写盘回读，实际运营和入住率待游戏验证。

## 对构建器的含义

静态证据支持把楼层当作业务机制的对照样本。中科技办公对照最容易隔离招工与生产，商场与办公的差集适合追顾客和补货，住宅和观光适合分别研究居民事务与游客事务。楼层整包移植到地面后的行为独立性仍待验证。科潘适合保留为地面住宅接入基线，威利斯适合保留为地面招工与观光集成基线。

若实现新处理器，先从中科技办公的一项机制切入。对每个候选记录，保留原版 bundle 的完整 TGI、父级和顺序，逐条核对规则库、参数绑定、bin、sink、事件、初始状态与路由端点。构建期缺引用即失败。现行配方与流程的代码入口为 [behavior_loops.rs](../../src-tauri/src/asset_build_m1/behavior_loops.rs#L62)、[behavior_templates.rs](../../src-tauri/src/asset_build_m1/behavior_templates.rs#L73) 和 vendored [behavior_profiles.py](../../reference/sc5-packager-0.8.0/behavior_profiles.py#L62)。真正的行为验证需在地面候选中观察各档劳工送达、在岗计数与产出，然后跨第二种建筑身份复核。此次未运行游戏或生成测试资产。
