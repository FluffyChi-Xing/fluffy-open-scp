## 管理器归属与速度字段闭合（续轮）

本轮找到此前管理器扫描零命中的直接原因：三个 `cTransportVehicle` 管理器候选位于 **PAGE_EXECUTE_READWRITE (0x40)** 页面，旧 `Protect & 4` 条件漏掉了它们。当前有车辆记录的管理器为 `0x2DF58398`，另两个候选的表为空。地址仅用于 PID 7424 当前生命周期。

零售 `0x721220`（vtable 0xD214BC +0x64）与开发版 GetAgent 的查表和返回模式相符；它取管理器 +0x1D0 的哈希表，调用 `0x720F90` 查找，并返回 node+4。查找函数直接证明：bucket pointer=map+4，bucket count=map+8，key=node+0，next=node+0x1DC；以 unsigned key % bucketCount 分桶。读取遍历检查了分桶关系及 node+4 的车辆 vtable。开发版 vtable 槽序与零售不同，不能机械套用。

`0x71B7A0`（RVA 0x31B7A0）与开发版 UpdateAgentInfo 的分支及数据流匹配：

| 零售字段 | 语义与指令证据 |
|---|---|
| agent+0x15C | 当前速度；与 +0x160 比较，经加速/制动后写回 |
| agent+0x160 | 目标速度；加速上限、制动下限 |
| agent+0x34 | 最大加速度，乘 manager+0x29C 时间步 |
| agent+0x168 | 本帧制动量，从当前速度减去 |
| agent+0x180 | 路径重算剩余时间；停止时减时间步，移动时重置 |
| agent+0x184 | 停止时间；停止时累加时间步，移动时清零 |
| manager+0x29C | 本次模拟时间步 |

`0x7346C0`（RVA 0x3346C0，零售 vtable slot 37）是 SimulateAgents 候选：非正时间步写零返回；正时间步按上限分段写 +0x29C，调用 `0x733E60` 推进。尚未通过 hook 观察此函数执行；名称归属来自静态控制流匹配。
