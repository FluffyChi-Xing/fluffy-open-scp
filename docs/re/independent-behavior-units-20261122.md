# 独立行为单元组合（实验实现）

**当前代码为 v3：无业务宿主＋全部业务组件。** 建筑宿主不再承载首组业务；办公＋观光编译为 1 个宿主和 2 个组件，六类组合为 1 个宿主和 6 个组件。以下 v2 构建记录仅保留历史，不能作为 v3 产物或运行期验收依据。

目标是按巨塔的模拟单元边界组合业务，而不是撤销同一 Unit 内的冲突检查。编辑器基础行为卡新增「独立组合（实验）」；旧文档缺省仍是共享模式。

用户澄清：这是同一栋普通建筑的多功能组合，不是巨塔式分层管理。行为隔离只用于避免本地状态与规则冲突；建筑只有一个总开关，关闭必须同时停止所有行为，开启统一恢复，拆除整栋一并清理。不提供分行为开关，也不以逐单元查看或管理作为交付目标。内部子单元只是实现手段，不能改变整栋建筑的操作语义。

正确的目标是一个无业务宿主加 N 个业务组件：办公＋观光应有 1 个宿主和 2 个业务组件；六类组合应有 1 个宿主和 6 个业务组件。宿主保留外观、道路接入、菜单、建筑级预算与生命周期管理，不拥有办公生产、商业交易、住宅入住、观光接客或教育规则。岗位和业务账本属于对应组件，对外信息按整栋汇总，不能继续将建筑岗位隐式分配给首个行为。

原版管理契约的续查证据见 [容器管理静态记录](evidence/container-management-contract-20261122.json)。**纠正早期解释：** `SC_RULE_EP1_TOWER_SWITCH_ON/OFF` 的 eventType=6，属于遥测，不能当作管理命令。真正的普通建筑开关界面调用 `runSelectedUnitAndAttachedPlayerRule`（`tmp/installed-school-game-ui.js:1889–1891`）；引擎 `RunUnitAndAttachedPlayerRule`（`docs/source-code/SimCity-dev-ida.c:1139967`）对宿主及 `GetModulesOfBaseUnit` 枚举的组件执行同一个 `0C614160` 规则。组件归属由连接关系和 nonSim `0AFE2FEB=true` 标记共同确定，宿主不得有该模块标记。v3 为全部参与者检查有效的原版 `44F5CF6C` 开关 provider。`cToolBulldozer/DestroyWholeUnit.c:174–207` 还会将宿主和连接单元加入拆除队列；这些是原版代码证据，v3 实际运行仍待验证。

## 编译与资源边界

工作台 `composition: independent-v1` 将每个行为叶子的 ID 写为 `semantics.behaviors[].unit`。`behavior_units.rs` 按 unit 分组，复用原有单体编译器分别编译；同一 unit 内继续执行原有配方及冲突校验，不同 unit 的字段、资源声明和 sink 不再互相比较。最多 16 个业务组件，全部位于内部子单元；外观和玩家菜单只有一份。宿主复用原版公共 Toy 骨架及基座排除表，不导入巨塔类别或楼层管理界面。新容器契约复用普通菜单、模型和 locale 检查，再严格检查无业务宿主和全部组件图；保留原有单体 Building40 的完整供体字段与用电检查不变。

子单元 ID 由宿主 ID 与 scope 哈希生成，碰撞则失败，不能覆盖已有资源。新增 `behavior_unit_build.rs` 负责边界装配，每个子单元从宿主行为修改前的供体独立起步，调用原有单体构建流程。观光继续使用完整原生地标路径。子单元不继承已经混入其它行为的最终主 Unit。临时菜单仅供旧 binder 的冻结校验，不进入输出。

子单元拥有自己的 Unit、无模型的 Lot 配置和路径表，按原版 secondary-unit 表挂到主单元。建筑级造价和维护保留在主单元，子单元不重复收取这两项建筑预算；业务规则的本地账本仍独立。显式节点 labor 仅属于自己的单元；独立模式不将原建筑级 labor 分给首组，编译 notes 明确提示。独立商业的缺省岗位取原版对应 D1 商店或 W2 巨塔商场。各组件岗位的完整编辑界面和整栋汇总面板仍待完善。

隔离针对 Unit 本地状态，不复制整座城市。道路、城市劳工和游客供给、规则明确使用的全局资源仍按原版语义共享；独立单元不能凭隔离本身保证满员或持续盈利。

资源闭包沿完整 TGI 保留新单元及其生成的构建/容量 bundle。golden-shape 只放行经过图验证、具有明确归属的新资源集合；模型、纹理和无关 donor 仍执行原有检查。最终 DBPF 写盘后再次回读验证挂载表、连接、子单元配置、路径和配方。程序未触碰 SQLite 启动边界。

**尚未完成运行期验收。** 独立单元自身支持的既有车行入口会分别注册；目前公园、地面住宅和小学配方没有被现有普通车辆适配器识别的接收表，所以只保留各自路径及行人接入，并在构建台账明确记录 `not-provided-by-current-profile`，不能借用办公的车行 sink 冒充自己的接收能力。住宅车行回流等仍需沿原版接收契约补齐。

整栋建筑总开关对所有行为的同步控制、整栋拆除清理、保存恢复、跨日补客及幸福循环尚未在游戏中验证；当前信息面板也尚未实现整栋建筑多行为数据汇总。因此本功能不能标为「所有完整行为已完成」。不需要也不实现分行为启停。
