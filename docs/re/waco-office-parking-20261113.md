## 车位导出缺陷

瓦科 Lot 的组 0 有 `CarW1/2/3`、15 个变换和 `0C12EF60=true`。15 个变换的 `0C12EF40` 只有两个不同值，前七个为 0，后八个为 1。大学的九个位置是 `0..8`。住宅＋观光对照的五个位置也有编号复用，分别为 `0,0,0,1,1`。原版住宅 `41E1C000:5EB99AC6`、商业 `42E1C000:A493781E`、工业 `43E1C000:60DE5E12` 的停车列分别使用 `0..26`、`0..4`、`0..13`。

引擎 [FillFromProps](../source-code/SimCity-dev-ida.c#L959113) 把该列逐行写入每个 transform 的 `mSlot`。[Update](../source-code/SimCity-dev-ida.c#L957181) 以该编号读取共享的 `mResourceSlots`，填入的车型来自模拟资源。因此，瓦科十五个位置最多只有两个独立槽号。静态导出参考 [prop_contract.py](../../reference/sc5-packager-0.8.0/prop_contract.py#L82) 用 `range(n)`，当前 [Rust 导出器](../../src-tauri/src/asset_build_m1/native_profile.rs#L695) 写的是该道具在资源列表中的位置。修复时应保留资源数组和变换顺序，使用独立车位编号，并在写盘回读时校验车位编号与坐标一一对应。

`0C12EF60=true` 时，更新逻辑将各车型的 `amount / capacity × 变换数` 向上取整。办公和基础劳工 bundle 的三档静态容量均为 `2147483647`。如果实机容量维持该值，常规数量下每个有库存的车型只会请求一个槽。零库存会请求零个槽。车位重复与百分比模式都需在修复后核对实际显示。两组正向对照也使用百分比模式。

## 到岗、驶入和停车

- **模拟。** 瓦科 A5 用 `61EFC700:1E16EDA9`，排除基础 `40E0C700:D07C5A04`，A3 仍包含 `30645625`。办公叶子的 sink 表由基础的 39 行改为 9 行。EP1 的 W1 驾车接收仍存在，从 `ADAF4C17 → C103DF03` 可达 `6273D02F/C85DC997`，两个规则都有本地 `CarW1` 的 `0→1` 写入。W2/W3 对应 `44AB9D52/AB3F739A`、`41BA177D/9BE1B0E5`。同一叶子的 `FBFBE6BF/BC751B82/4D359069` 可以走只增劳工的分支。基础 `30645625` 的 W1 `DB144779→79EFCA71` 也可达同一停车写入规则。两组 W1 驾车 sink 接受车辆 handler `54ABDF8C`，但 key 资源和控制条件不同。303 名劳工无法反推出其中有多少车辆、哪个 sink 接收或停车库存。
- **地块内行驶。** 瓦科车道是 `40E0C400:03106C2E`，三个点，`Local + None`。大学和住宅＋观光也使用同类型本地车辆路径。原版小学有独立的校车 `7C9C4FFF` 路段，`Global + First`，另有本地车道和人行道。瓦科与大学共用 Unit 的内部路径过滤器 `0DA69D6F=2C7C7986`。这些静态字段能确认路径已写出，无法确认放置后车辆 sink 能否通过外部道路到达，也无法证明车辆事务沿地块内几何播放。
- **观光和 RCI 对照。** 住宅＋观光对照同时有住宅、劳工和观光规则，画面出现车辆本身无法归因给观光。该包的住宅 `AB9A0A3E` 已能通过 `487E1CC6→104D6998` 到达 `A450870F`，将附近事务的 `CarW1` 转入本地。原版商业、工业和住宅共有停车绘制机制，各自由不同的模拟规则写入车辆资源。

运行验证需要在同一班次记录瓦科 `CarW1/2/3` 的 amount/capacity，核对车辆 sink 容量与事务送达，并分别观察外部道路、地块内车道和停车位。如果库存为零，追车辆派发和接收。如果库存为正但车位仍空，追槽位和图形资源绑定。此次未采集运行值。原始包回读和 AEB 规则展开位于 `tmp/megatower-re-20261113/parking-live.txt` 与 `parking-sinks.txt`。

## 车位修复后的实机读数

部署包 SHA-256 为 `80ec93b28c015b1cbc74574064e0497373bed011689da462821b830cd75359a8`。用户报告地块仍无车驶入。对已运行的零售版 SimCity PID 24616 进行进程外只读采样，定位到 `DDD772B5`、slot 588。76 个同 tick 快照覆盖 tick 29623–29642，建筑一直运营，劳工从 171 增至 177，三档 CarW 一直为 `0/2147483647`。tick 29713 再读时，瓦科有 208 名劳工，车辆仍为零。同 tick 全城 335 个带车辆 bin 的单位中 245 个库存为正，其中 26 个也有劳工。证据位于 `tmp/waco-live-24616/`。

办公车辆 sink 的三档默认 key bin（`8FFE677B/82ECBDB0/EE3B875D`）在采样中均为零。基础劳工车辆 sink 的三档默认 key bin（`E7C205B5/1899BE36/E63C1FF3`）为 100/64/3。还需把这两组 key 值与各 sink 的实际有效容量、控制位及道路挂接关联。key bin 读数单独无法确定事务是否有候选路由。

原版住宅、商店和工厂的抽样 Lot 有 `0CFFE03D` 与 `0CFEC186`，用于把指定 sink 绑定到指定地块路径，如 `C34881E7`。瓦科包缺这两列。引擎 [AddSinkPositionsFromDataPaths](../source-code/SimCity-dev-ida.c#L1089055) 先查显式绑定，再在 [车辆接收位置初始化](../source-code/SimCity-dev-ida.c#L1092071) 尝试默认路径、最后尝试建筑原点。普通车的默认 PathEntry 是 `03106C2E`，瓦科已包含。因此缺显式绑定是待对拍的差异，仍需读取车辆 sink 的路段与容量，判断是接入失败还是派发未选中。

## 同城有车地标对照

同一进程内，不知名建筑大厦 `A0BF22FD` 是 slot 477，瓦科仍为 slot 588。tick 29713 时，该地标有 45 名劳工及 937/1100 的 `CarW1`。tick 30353–30371 的九个同 tick 快照中，两栋楼共有的三档基础及办公驾车劳工 sink 容量均为零。地标的住宅返家 sink `F880AFAB` 仍有 37–38 容量，`5B18518D` 仍有 98–100。两条都能将事务携带的 `CarW1` 加进地标的本地停车库存。瓦科没有这组住宅返家规则。车辆实际进出的具体事务类型尚未逐车采集。

零售版 `SinkCapacity`（RVA `1CB550`）读取 Unit `+0x200` 的 64 位控制位和 SinkEntry `+0x30/+0x38` 的掩码及期望值。tick 31229–31239 的八个同 tick 快照中，两栋楼都在模拟，三档基础、办公驾车劳工 sink 的唯一控制位不匹配都是 bit 49 实际为 1、要求为 0。引擎在控制位不匹配时直接返回零容量，发生在资源检查和道路挂接之前。地标的住宅接收点未受该位拦截，`F880AFAB` 和 `5B18518D` 容量分别为 111 和 100。后续需要确认 bit 49 的置位来源和班次边界上的变化，再决定如何接入办公驾车通勤。两栋楼的快照分别在 `tmp/waco-live-24616/sink-compare.json` 与 `sink-flags.json`。

## 普通车道构建处理

瓦科 Unit 的初始位数组 `0A88D179=[14,49,23]` 已能解释运行状态。引擎 [AddBundle](../source-code/SimCity-dev-ida.c#L699252) 读该列并将每个位 OR 到 UnitEntry。原版接收表 `30645625/D07C5A04/1E16EDA9` 的车流接收条件及两列 Lot 绑定作为取证基准。Packager 0.8.0 中对应的配置惯例见 [behavior_profiles.py](../../reference/sc5-packager-0.8.0/behavior_profiles.py#L62)，该版本没有此车道接线处理。

显式绘制普通车道时，[构建处理器](../../src-tauri/src/asset_build_m1/vehicle_paths.rs) 根据 Unit 已启用、未排除的原版配方接线。地面通勤保留其余初始位并去掉 `49`，住宅返家和观光等使用原有接收点。当前配方无已知普通车辆接收点时构建失败，最终 DBPF 回读也校验接收绑定。瓦科副本完整构建通过，回读 `0A88D179=[14,23]` 和九条车辆接收绑定。不知名建筑大厦副本也通过，保留 `[49,22]`，输出六条住宅和三条观光接收绑定。两个副本仅供离线验证，本轮尚未验证车辆派发、道路挂接和库存变化。

## 车位填充数量

用户随后观察到三个财富档各只显示一辆车。已核对实机基线与构建产物的 SHA-256。Lot 的 15 个独立车位均已写出，但 `0C12EF60=true`。引擎 [Update](../source-code/SimCity-dev-ida.c#L957101) 对每档按 `ceil(amount / capacity × 15)` 请求车位。瓦科三档车辆 bin 的容量均为 `2147483647`，所以常规数量下每个有库存的档位只请求一格。原版地面住宅、商店及工厂对照的停车组未启用百分比，[Packager](../../reference/sc5-packager-0.8.0/prop_contract.py#L84) 也将该开关写为 false。

地面通勤接线现在将停车组切为按实际数量填充。瓦科候选包 SHA-256 为 `788d71be031c2a7b98fcccf91b3d4f6f4b68c61352741787d0c4dd32b80b0ff5`。20 个资源身份一致，属性回读仅 `0C12EF60` 由 true 改为 false。候选未部署，显示数量待实机验收。

## 地面演出

已确认的瓦科部署包有 5 个演出锚点，缺少演出的注册列 `0D2E8A55 / 0D5A28B8 / 0D50908D`。构建器此前只为教育和观光选择演出。地面资产有自定义演出锚点时，有岗位容量则选用原版 Lot `C8ACE042` 的演出 `2A29A2A5`（4 个锚点），其余选用原版 Lot `8B741349` 的演出 `9A84297C`（2 个锚点）。两条定义均允许自动启动（`0D93D08C=true`），演员条件均为 `ActiveBuilding`。构建器复用锚点映射，最终包缺少注册行或所需锚点时构建失败。

瓦科停车与演出候选包 SHA-256 为 `60c768c5167285eddb9854b3d3cb7ab901be0c59d0637417a810edfd4a840d71`。离线回读确认 20 个资源、停车组 `0C12EF60=false`、办公演出行 `195CD654 → 2A29A2A5`、4 个所需锚点和第 5 个自定义锚点。候选尚待实机验收。
