# OmegaCo 工厂运行时观察（2026-10-23）

本轮以城市发展菜单中的 `OmegaCo工厂`（UnitEntry `0x071D31E5`，UI 名称 `T_EP1_OmegaCo_Factory_Base_01`）为对象，观察同一城市中 6 个实例：slots `63、70、170、418、485、561`。

## 采集身份与窗口

- 进程 PID：`28160`
- EXE：`D:\ea-games\simcity_offline\SimCity：Cites of Tomorrow\SimCity\SimCity.exe`
- EXE SHA-256：`2b0aff527baa3aa536aca6c68332c208d1dbd904695f0f985d17d56b128d48ab`
- 资源快照：请求 300 秒、以 360 tick 为停止条件，实际 279 个样本，tick `48440 → 48801`（约 140 秒墙钟时间）；每约 0.5 秒一次；进程外 `ReadProcessMemory` 只读，未注入游戏逻辑。
- effect 捕获：120 秒，2000 条记录；Frida 正常卸载，`errors=0`，但达到上限并丢弃 2272 条，因此是定向样本而非全量吞吐统计。

原始证据位于 `tmp/omegaco-resource-watch-20261023/` 与 `tmp/omegaco-effects-20261023/`；汇总文件为 [`tmp/omegaco-analysis-20261023.json`](evidence/omegaco-factory-runtime-20261023.json)。

## 观察结果

六个工厂均存在电力、水、污水、维护费、总劳工/W1 劳工、所需劳工以及 W1/W2/W3 工作槽。实例之间的活跃程度不同：slot `170、418、561` 的库存变化最丰富，适合后续做单实例深挖。

- **劳工**：`TotalWorkers`、`WorkerW1` 和 `WorkersNeeded` 都出现在六个实例的本地资源集合中；同时有 `JobsW1/W2/W3`，说明工厂至少维护多收入层级工作槽。当前快照只证明字段和变化，不能把数值解释为持续在岗的具体市民数量。
- **电力/水/污水/垃圾**：电力和水是六实例稳定出现的基础服务资源；污水、垃圾也在资源集合中。快照是非原子读取，短于采样间隔的消费或排放可能被漏掉，因此“某实例端点未变化”不能证明没有瞬时消耗。
- **原矿/原油**：已确认的 ID 在 effect trace 中高频出现：原油 `0xbf75dc04` 238 次、原矿 `0x96cf3b07` 227 次（按 2000 条截断记录内的 operation 计数）。这比单看库存端点更强，证明 OmegaCo 的本地规则确实频繁读写两类投入资源；由于采集有 dropped，不能将计数外推为完整生产率。
- **处理器**：工业处理器 ID `0xbee1c73e` 已静态确认，但本轮截断 effect top 列表中未形成与原油/原矿同样高的可闭合频次；它更可能属于总部/无人机组装链或库存状态之一，后续应按该 ID 单独定向捕获。
- **Omega 生产**：静态 UI 说明和本地化文本闭合了“原油 + 原矿 → Omega”的设计关系；运行时本轮能确认共同生产/消费规则和大量候选库存变化，但没有足够证据把某个候选 ID 命名为 Omega 成品，也没有完整的输入输出配对日志。因此当前结论是“观察到生产链活动”，不是“已测得 Omega 每小时产量”。

slot `170` 出现 `0xd3c17458` 从 0 增至 4800、`0x77f787d7` 与 `0xae6ddfed` 增至约 4500，并伴随多个 150/300/450 步长变化；slot `418` 有多项库存从约 35000 降至约 20000；slot `561` 的多个候选库存持续增长。这些是实例库存净变化，不应直接当作消费总量或产量。

effect 聚合中规则 `0x645b10e4` 同时覆盖六个工厂，并集中操作原油/原矿相关资源；其他高频规则包括 `0x938552f2`、`0x549d25c3`、`0xeed48efb`、`0xc85dc997`。规则 ID 已记录，但尚未完成函数级名称解析，不能据此断言单条规则就是“生产”或“运输”。

## 证据边界与下一步

快照是非原子、低频采样；净变化不等于完整吞吐量，也不能单独建立规则因果。effect 捕获受 2000 条上限影响，存在 2272 条 dropped。建议下一轮暂停其他 Frida 采集，分别以 `0xbf75dc04`、`0x96cf3b07`、`0xbee1c73e` 和已识别候选成品 ID 做短时单资源捕获，并提高上限；同时读取 slot 170/418/561 的前后库存，闭合“原油/原矿输入—Omega 输出—运输库存”的配对关系。
