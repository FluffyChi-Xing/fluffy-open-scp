# 希望大厦原版柱图汇总接线

## 结论与修复

容器改造漏掉了零售版原生分组字段 `nonSim 0FB2DB9A = Bool(true)`，使各业务组件按自身原点独立绘制，彼此重叠。此前只复制包围盒没有修复此问题；“多个 Unit 因而无法由原版统一排列”的推断不成立。

新增 `behavior_container_bars.rs`，在宿主及每个内部业务组件的 Asset 上写入该原版 Bool，沿已有连接及模块标记启用基座汇总，不移动 Unit、不更改路径、不新造统计数值。前置菜单契约和最终 DBPF 回读都要求全部参与者具备该字段；漏掉任意一个则拒绝构建。旧共享行为编译路径保持不变。

## 当前安装版的代码证据

安装版 `SimCity.exe` SHA-256 为 `2b0aff527baa3aa536aca6c68332c208d1dbd904695f0f985d17d56b128d48ab`。分析使用工作区 IDA 数据库副本；该数据库原始输入文件 SHA 不同，所以每个关键函数都重新将数据库的完整函数代码范围与当前 EXE 对应范围逐字节比较，相同后才作为证据。详见 `tmp/retail-bars/callers.json`。

- `0x7A7D90`：有效 Unit 的 nonSim 属性查询 ID 为十进制 `263379866`，即 `0FB2DB9A`，要求原生 Bool 且值为 true。
- `0x7A7C90`：用 `0AFE2FEB` 判定基座/模块。
- `0x7A8A00`：沿连接关系将模块解析回基座。
- `0x6ACFE0`、`0x6AD8C0`：模块满足上述分组条件后，对基座调用 `0x6A9F90`，并隐藏模块重复柱图。
- `0x6A9F90`：枚举基座及模块，按资源 ID / UIKey / 属性类型匹配，合并柱图 amount 和 capacity；零售版汇总组最大 6 项。
- `0x6AF080`：实际更新两套表：普通 Unit 表及基座汇总表。
- `0x6AC400`：对组内柱形按 footprint 横向排列，基于汇总数量缩放柱宽；单条柱形记录为 120 字节。

原版 Asset 回读：巨塔基座父 `61F0C000:0229A393` 和冠楼父 `61F0C000:337D999E` 均写 `0FB2DB9A=true`，冠楼父还写 `0AFE2FEB=true`。它是原版模块汇总接线，不需要引入巨塔楼层管理界面。

**版本纠正：** 此前保留的开发版代码只有一套 Unit 表，柱形记录为 116 字节、组上限 4；不能用它断言当前零售版不存在基座汇总。开发版源码可用于寻找候选功能，具体零售行为须继续核对当前二进制和原版资源。
