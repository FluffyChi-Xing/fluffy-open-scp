# 行为容器与自定义 Panel 兼容性核查

结论：**目前不能确认“住宅以外全部行为问题已修好”，也不能确认“容器模式不会影响自定义 Panel”**。这是当前代码核查与真实构建复现的结果，不是仅凭推测。

## 非住宅行为的已验证范围

独立 scope 已覆盖办公、观光、商业、公园、教育，完整构建及最终回读验证各自的配方、资源和连接归属；同 Unit 冲突检查保留，不同 Unit 隔离冲突。希望大厦已获用户实机确认柱图、夜间窗灯及当前原版游客面板显示正常。

但隔离不等于业务运营闭环全部修复。跨日观光补客、商业持续消费、教育/公园的完整出行与运营仍未全部进行游戏验收。当前普通车辆适配器对公园、住宅和小学仍可能记录 `not-provided-by-current-profile`；不能将构建通过解释为这些出行能力已完备。住宅不列入本次确认范围。

## 自定义 Panel 的实际兼容缺口

1. `stages.rs` 在 behavior-bind 后执行 opt-in panel-bind。`panel::processor::apply` 将宿主 Asset 的 hover/click/header 项替换为自定义 `OpenSCPPanel_*`。
2. 随后的 `behavior_container::validate_menu` 调用 `behavior_container_ui::verify`，仍要求 hover/click 精确等于默认原版维护费/游客项，人口头精确等于 `kPopulationNone`。因此合法的自定义 Panel 被默认显示检查拒绝。
3. 自定义运行时里，岗位计数和每日利润等原版查询仍包含本地 `units` 源。容器宿主不再拥有组件业务数据。即使消除上面的构建冲突，也不能直接声称计数与财务数据正确；需要按模块的数据语义适配组件查询或汇总，并避免重复账本/错误求和。

修复时必须新增容器专用兼容层；保留默认面板与既有非容器自定义 Panel 路径，不能简单删除闸门或把所有查询机械替换为 connectedUnits。

## 可复现证据

- 工作区项目：`tmp/container-custom-panel-check-20261123`，从希望大厦容器项目复制，未修改用户原项目。
- 在 package.json 添加合法 `dependencies.panel`，从本机原版 `SimCity_Game.package` 读取原版 shell 和 game-ui 源，并核验源 SHA。
- 自定义 hover/click 仅选择 maintenance、tourists，power=true。
- 运行 `target/debug/openscp-build.exe tmp/container-custom-panel-check-20261123`。
- 真实失败：`[menu-contract] CONTAINER_UI: host-only or unbound rollover query`，见 `tmp/container-custom-panel-check-error.log`。
- 既有 Panel Rust 回归：9 项通过、1 项忽略（`tmp/container-panel-existing-tests.log`）；这些测试未覆盖“容器＋自定义 Panel”，不能拿它们证明组合兼容。

本次是核查，没有修改行为或 Panel 实现，没有替换游戏包。已验证的希望大厦 GOLDEN 包继续保留。后续兼容修复仍须保住所有渲染契约和已验证字节，并分别报告编译层与游戏运行层结果。

## 续修结果

容器自定义 Panel 按作者配置验证布局资源、悬停、点击、人口头和整栋总开关。在菜单检查和最终 DBPF 回读阶段执行同一规则。默认面板仍执行原有检查。

当前已通过构建的统计项为维护费，以及具有原生观光组件且没有商业或酒店容量混入的游客统计。原生游客统计以连接单元购物池为分母，商业或酒店混合时暂拒绝启用该项。岗位、利润等仍待实现有明确归属的取数，构建会明确拒绝这些配置。在容器自定义面板中保留整栋开关。

希望大厦原复现项目通过完整构建及回读（30 个资源），办公、观光、公园、商业、教育五组件组合配自定义维护费面板也通过（33 个资源）。不支持的游客分母、利润及取消总开关均经 CLI 反例验证。希望大厦候选与 GOLDEN 先验哈希后对比，仅宿主面板字段变化并新增布局，全部其它资源 payload 一致。候选 SHA-256 为 `a785fd75a6a7c0a0cd58cba2d93c920cdb6f12399b6a38c88a16d160774193aa`。候选用于工作区对拍，游戏安装仍为已验收版本。游戏内自定义面板显示和非住宅跨日运营仍待验收。

## 商业与独立观光组件共存

自定义游客行继续查询连接单元的三个游客资源。分母改为建筑宿主面板属性 `94D45158`，从最终写入的独立原生观光 Unit 中读取 `0AD6A725` 并汇总。它表示配置容量，编译与写盘回读均验证来源和数值。商业组件自身的购物池不计入；商业和观光共用同一 Unit 或存在独立酒店时仍拦截该游客行。

在办公、观光、公园、商业、教育五组件夹具中，加入游客行后完整出包和回读通过，分母为观光组件配置的 175。对拍只增加宿主的点击行和面板容量字段。业务 Unit、接线路径、模型、纹理、灯光与统计柱资源保持相同字节。新增游戏 UI 脚本只附加到需要这个游客行的候选运行时，其解码内容以旧运行时的完整字节为前缀。旧游客行保留独立的处理器。游戏内复测尚未进行，也没有部署运行时或建筑包。
