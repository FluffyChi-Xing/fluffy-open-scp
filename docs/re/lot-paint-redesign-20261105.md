# Lot 地面绘制重设计与油漆桶修复

## 研究结论

`ny_facade/lot_paint.py` 的可用模型是“材质区域绘制”：作者选择一个地表预设（颜色、图案、周期、粗糙度），再用画笔、矩形或连通填充修改区域。Lot mask 只是导出缓存，不应该成为用户的工作对象。

游戏侧实际是两层独立数据：LotMask 的四个通道决定“哪里覆盖”，而 LotColor1–4 的 RGB 决定每个覆盖区域的独立染色，LotColor 的 A 分量决定 4×4 图集中的 16 个纹理/法线格（0–15）。未覆盖区域还由 `0x0CCB7FD6` 选择一个底图格。边框也有独立的 LotBorderColor1–4、边框图集索引和宽度。也就是说“四个材质层”是四个可染色的选择器，不是只有四种地面纹理。

当前编辑器已经具备这个数据流：`RasterDocument` 保存像素，`lot.colors` 保存四种材质参数，`RasterMaterialPanel` 保存颜色/图案，`RasterPreviewPanel` 显示最终地面。问题主要是 UI 把内部术语暴露给用户（LC、通道、Lot mask），并且绘制坐标和预览坐标没有统一的视图变换函数。

## 目标工作流

1. 载入或新建“地面绘制”资产，编辑器自动选择默认基础地面和 0.75 m/px。
2. 在右侧为四个地面选择器分别设置染色颜色，并从完整的 4×4（16 格）纹理图集中选择图案；显示“基础地面、草地/绿化、道路/步道、装饰/细节”等语义名称。
3. 选择一种材质后直接使用画笔、矩形、多边形或油漆桶。作者不需要知道 R/G/B/A 对应关系。
4. 3D 预览显示材质合成结果；保存时自动写入 Lot mask，导出时自动处理资源和尺寸。

后续组件化建议是把“材质预设”和“绘制工具”拆成独立的 `LotPaintSurface`、`LotMaterialPalette`、`LotPreview` 三个组件，并让它们只通过一个 `LotPaintState` 接口通信。这样 Asset 编辑器可以嵌入同一绘制面板，而不依赖 Raster 页面或底层 profile 名称。

`LotMaterialPalette` 应继续保存以下字段：`color`（独立染色）、`patternIndex`（0–15）、`borderColor`、`borderPatternIndex`、`borderWidth`，以及 `baseTileIndex`。其中颜色是每个选择器独立的线性材质颜色，图案索引只引用全局图集，不复制纹理资源。

## 本次实现

- 新增 `viewportToPixel()`，统一处理画布 wrapper 的平移、缩放和指针坐标。
- `RasterCanvas` 改用该转换；居中或平移后油漆桶的种子像素与用户点击位置一致，封闭区域可以正常填充。
- 将 Lot 引导文案和四个选择项改为材质语义名称，隐藏通道和 mask 术语；底层 schema 与导出格式保持不变。
- 新增 4×4 的 16 格图案选择器；每个选择器的图案索引仍写入颜色数据的 A 分量，独立颜色继续写入 RGB。

## 边界

油漆桶仍按像素连通区域工作。导入图片若有抗锯齿边界，应提高容差；真正的矢量边界编辑属于后续 `LotPaintSurface` 迭代，不应混入当前 Raster schema。
