# 公交两站循环的静态证据

沿 [市区 T2 公交样本](./municipal-bus-transport-20261113.md) 核查普通站牌 `FE043FDC` 的重复派送。零售 AEB 可证明规则允许同一辆车重新进入同类站台候选池，原生反编译可解释该候选池如何通过资格检查。具体存档是否发生连续的 A→B→A、同一批乘客是否一直在车上，仍需运行记录。

## 脚本给出的循环边

1. `FE043FDC` 的 T2 bundle `42F3AD5E` 把普通停靠 sink `377AA3B3` 直接映射到 `288A753D`，把 `F5830EFB` 等接客 sink 映射到 `B28D5831 → 288A753D`。一辆车抵达另一座相同站牌，会再次进入这套规则。
2. `288A753D` 扣掉站台本地的 `E773C1BA` 服务令牌，容量和初值均为 1。 `377AA3B3` bundle 的 `34DCA533` 在 Day 06:00–18:00 的 Hour 触发窗尝试补回该位。 `377AA3B3` sink 正是用该资源确定可服务性。这个门槛是**每站共享的服务状态**，具体到一辆车的最近停靠序列无法从该令牌还原。
3. 到站链中的 `D7268301` 检查事务的 `BusPassenger` 至少为 1，失败转到 `03D4180A`。另一条到站分支 `FAAE1120` 的失败边也指向它。 `03D4180A` 检查车上有一辆 `BusT2`，并对 `377AA3B3` 执行 AgentTest。上界的原始浮点位为 `0x7F7FFFFE`，比 `FLT_MAX` 小一个浮点单位。
4. 检查通过时，`03D4180A` 可将**同一个车辆事务**重定向。它的候选序列为 `377AA3B3, F5830EFB, B2FC5BFF, 377AA3B3, 9DDB15A8, 9584AE26`，life 均为 `(-1,-1)`，由 `GetInitialDestinations` 组成一组。候选仍有触发本规则链的普通站台类型。检查失败时，`ED032509` 改用只含 `9DDB15A8/9584AE26` 的回收候选组；另一条 `8FBE0801` 也能请求该组。

## 原生侧的实际判断

`DoAgentTest` 先要求目标类型池存在且总容量大于零。该样本的上界与 `FLT_MAX` 的位值 `0x7F7FFFFF` 不同，所以走道路挂接与端点距离检查。它要求某个服务对象在范围内，检查中没有读取本车最近的停站序列。实际方向与站台分配在车辆路由和停靠时继续判断。见 [AgentTest](D:/ea-games/simcity_dev/SimCity.unwrapped.exe.c:1089853)。

`DoRedirectTransaction` 在原事务 slot 上更新 `mRuleIndex`、`mSource` 与出发位置，`03D4180A` 的 `mTransportID=0` 保持当前车型。 `SetInitialDestination/UpdateDestination` 根据候选类型的路径池、可达距离和 sticky 候选索引选择；`CheckSink` 再看路段、方向和可分配容量。核对的这些路径没有按事务排除“上上站”或累计 A/B 交替次数。该结论限定于所列反编译路径。见 [重定向](D:/ea-games/simcity_dev/SimCity.unwrapped.exe.c:642758)、[初始目的地](D:/ea-games/simcity_dev/SimCity.unwrapped.exe.c:1090003)、[更新目的地](D:/ea-games/simcity_dev/SimCity.unwrapped.exe.c:1089966) 和 [停靠](D:/ea-games/simcity_dev/SimCity.unwrapped.exe.c:890001)。

因此，假设 A、B 在各自到站时都走到重新派送分支，且另一站再次满足容量和道路条件，`A → B → A` 在静态规则图中可重复。另一站可以因新的候车需求、其他兼容 sink 或服务令牌恢复再次进入候选。没有观察到相同乘客往复的事务轨迹，不能据此认定某一批人被无限运送。若局内只有车辆在道路上绕圈且没有成功触发站台 sink，应检查原生路由和交付失败，脚本循环有不同的可观测证据。

## 版本对拍

Maxis Update 2.0 公告记录过接客或下客循环，并说明会让卡在循环的车辆回车库。公告也提及优先服务高客流站。下表是本机脚本包的记录级对照，未建立包内部版本号到该公告的对应关系。 [Maxis Update 2.0 公告转载](https://www.gameinformer.com/b/news/archive/2013/04/19/major-simcity-update-coming-on-monday-april-22)

| 安装包版本 | `03D4180A` 失败边 | 回收候选 |
|---|---|---|
| `257365692` 至 `269107214` 的六个样本 | `1ED4FA76 → 043144A2` | `043144A2` 只含车库和备用 sink |
| `272391411`、`275765162` | 直接 `043144A2` | 同上 |
| `277393341` 至 `287520926` 的五个样本 | `ED032509` | 同一对 sink |

这些版本的 `03D4180A` 保留了包含 `377AA3B3` 的六项候选序列。早期 `1ED4FA76` 可先尝试另一组接客候选，随后版本删去这一层。该对照能证明**脚本可控制何时继续派送及何时收车**，仍不能把公告中的具体修复归到这几条修改。

对 OpenSCP，静态规则图可以标出会重新进入站台候选池的边和回库边。要把某个存档的问题定位到规则，需记录同一个事务的成功停靠站序、重定向 rule ID、候选类型和乘客 bin 的前后值。公交这一结论也不能直接推广到铁路、校车或消防车各自的规则和处理器。
