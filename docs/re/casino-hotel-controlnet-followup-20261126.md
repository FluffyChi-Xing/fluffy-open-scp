本轮读取原版安装包、属性、AEB 规则和面板脚本。结果用于定义节点配方。游戏内运营、生产构建和实时采集仍待验收。

## 博彩与客房连接

罗马赌场 `A94FB11E` 已有博彩接待与住宿核心 `352F4263`。两者共用赌场接客 Unit，初始空房为零。对此原型，添加一个正确连接、财富档匹配的客房模块即可让住宿入口获得空房。房客需要来自真实到访的游客，空房数也限制实际入住量。

W2 内部转房 `4EEE2726` 将游客从本场博彩库存转入房客库存，同时归还博彩接待位、扣掉一间空房。退房后，`6B2532D1` 在有博彩接待库存时做反向转换，否则走其他目的地或离场。城市游客也可直接经住宿入口入住。博彩现金结算读取在场三档游客，住宿路径读取和写入的经营 token 还需单独追踪。

工作台配方可让博彩与酒店共享一个接客 Unit，让各档客房作为容量发布模块。纯酒店可用原版普通酒店 `729A6626` 的直接初始化方式。组合配方应在构建期检查每档容量的发布对象、入住扣减对象、撤回路径和接客开关，避免发布到一个 Unit 却从另一个 Unit 扣房。纯博彩、纯住宿、同场住宿、满房与撤房应分别验收。详见 [原有赌场规则研究](casino-hotel-core-boundary-20261125.md) 和 [酒店容量语义](base-utilities-and-hotel-followup-20261125.md)。

## ControlNet 设备站

EP1 菜单 `00B1B104:61F0C900:1AC9FFB4` 使用名称文本 `0FADD5E2`，并引用 `74AFA83E`。对应规则 Unit `00B1B104:61EFC000:74AFA83E` 提供低、中、高收入岗位 `25/50/100`，生产门槛原始属性值为 `1`。其生产提供器 `8936DD32` 也用于 `6F08CBF7`，后者的岗位配置为 `50/100/200`。

原版 UI 常量资源 `67771F5C:A31E060F:05AFD67D` 将 `0FF564C9/CB/CD` 命名为三档 ControlNet 换算率，本站属性值为 `1/2/4`。`0FD16BE4` 是原版面板乘用的 `AcademySkillProducer_Rate`，值为 `6`。因此设备站不计模块时的原版面板公式是：

```text
面板每小时折算 = (60 / 6) × (实际 W1 工人 + 2 × 实际 W2 工人 + 4 × 实际 W3 工人)
满员面板潜力 = (60 / 6) × (25 + 2 × 50 + 4 × 100) = 5250
```

原版 `kAcademySkillGenerated.update` 用 `60 / AcademySkillProducer_Rate` 计算小时倍率。满员值也与设备站 `AA5FE358` 的原值一致。实际配送量取决于覆盖、需求、运行周期和消费者状态。原版面板会另加模块贡献。

1. **到岗。** `27DFB0D6` 声明 `AcademyWorkerW1/W2/W3`（`97235AA7/A4/A5`），`546ABF0F/0C/0D` 分档写入，另有清理与全城登记。面板直接查询这些在岗量。
2. **生产。** `8936DD32` 的多个 hour 周期入口刷新上一轮库存，继而执行 `8958BBCB → 8958BBC8 → 8958BBC9`。三条规则读取并保留各档在岗工人，将相应换算率绑定到 `AcademySkillGenerated (FCAB1E3F)` 的输出。共享配方也有独立的 `SkillTokenE3` 输出槽，设备站没有设置 `10132F63/65/67`，而对照 Unit `6F08CBF7` 设置了这三项。
3. **供应。** `6454E4DA` 将 `AcademySkillToken (7129E6D3)` 送向 `61EFC500:26A2E32F`。该 sink 使用径向处理器 `1A65986C`，以 `AcademySkill (5737C2E4)` 为 key resource。EP1 AEB 的 `B4E28D19` 明确用传入 token 增加接收方的 `AcademySkill`，融合电厂规则 `674C1853` 直接消耗这个 bin。生产量、配送 token、接收端库存和连接状态各自有资源字段。消费者完整挂接链、径向距离的属性换算、区域出口、停复机与拆除时的撤回仍需逐项核对。

## 工作台节点边界

首版节点可叫「ControlNet 生产」。公开三档岗位和对应换算率，由编译器复用 EP1 原版接岗、刷新和径向供给契约。面板用节点自身的三档实到人数、产出与配送累计，另从原生消费者采集库存和连接状态。学院研究、科研翼、解锁与跨城交易留待各自验证。设备站已有独立生产原型，因此可以先验证无学院研究模块时，站点是否独立向真实消费者供给。

首轮验收覆盖零工人、三档逐一到岗、混合到岗、满员、消费者进出覆盖、整栋关闭再开启和拆除。至少用一个真实原版消费者核对到岗、面板产量、实际接收和恢复。组合测试还需检查共享公共服务、项目构建及包回读、统计柱和日夜渲染。
