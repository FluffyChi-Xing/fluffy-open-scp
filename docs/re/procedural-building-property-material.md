# 程序化建筑 Property TGI 材质入口

## 实现结论

程序化建筑面板现在接收完整的 Property TGI（例如
`00b1b104:61f0c000:1d261fdd`），从已打开 package 中解析 Property，跟随它的
首个可用 LOD 模型引用读取 LOTM 材质容器（优先 LOD1）。解析结果会自动使用建筑材质的 tint、palette、
shader、interior、normal、roughness、AO 和参数表，生成的盒体继续使用程序化几何。

源模型的 building4 网格结合窗洞覆盖率和三角形面积选择代表立面，屋顶独立按面积选择：

- `uv1.x` 保留材质参数列，`uv1.y` 保留内景 seed；
- `uv2` 保留 Base facade 的世界投影；
- `uv3` 保留 Top facade 的世界投影。

因此精细渲染可以进入已有的 `meshUvKinds=2` tint shader 链，不再把建筑退化为只
有普通 `baseColorPng` 的灰色白模。地面部件仍使用简单颜色，避免把 Lot 地面遮罩
误当成建筑立面材质。

## 探针对应的限制

金属住宅的负/大 Top padding 和内景区域会随源参数表保留；全玻璃写字楼的玻璃
主要来自 Base 层，代码不会强行叠加 Top 窗口图层。广告牌、独立装饰物和源模型
的空间布局不会复制到新几何，只复制代表材质链和 UV 密度。

输入解析要求三段八位十六进制，且第一段必须是 Property 类型 `00b1b104`。若
关联 package 未打开、Property 没有模型或模型没有完整 building4 数据，面板会给出
可翻译的错误状态；切换语言时输入、状态和错误文案同步更新。

## 验证

类型检查、生产构建通过；25 项相关测试覆盖旧网格路径、新 GLB UV 往返、多材质绑定、
参数列按面积选择、跨包 LOD 解析、输入防抖/过期请求和中英文切换。

使用 `npm run dev` 后打开 `/tools/procedural-material-webgl.html`，可复现真实提取
数据的 WebGL 检查（依赖已有 `tmp/future_planes/{5a6ec67a,1d261fdd}` 探针输出）。
此工具从探针的 mesh.json 重建源 GLB，再运行生产代码的分析、生成与 building4
着色器。内景 seed 使用固定 0.25，灯光是检查用的固定环境，不是游戏截图对拍。

2026-10-21 首轮（修复前）实测：金属住宅自动选择立面列 3 / 屋顶列 10；玻璃写字楼选择立面列
7 / 屋顶列 1。两者各生成 456 个三角形，WebGL 程序均可运行，无着色器错误，
分别显示金属墙板和玻璃窗格。后续用户反馈确认：只选面积最大的主体墙板会丢失
窗口，不能作为程序化立面的默认选择策略，修正如下。

本轮没有通过桌面 Tauri 界面进行实际 package IPC 点击验收；跨包链路有模拟 API
测试，真实纹理和网格已在浏览器 WebGL 中验证。导出 `.building.json` 保存 Property
TGI、实际 LOD、模型 TGI 和 package 路径，不嵌入游戏 PNG。

屋顶候选限制在模型上半部，避免大片地面参与选择。玻璃楼上半部仍选择列 1，
其绿色顶面是当前代表材质结果；没有证据将它断言为地面草坪误用。

## 窗户丢失修复（2026-10-21）

回归资产 `00b1b104:40a2a11f:10daf7bf` 来自 Graphics 包，LOD1 模型为
`2f4e681b:00000000:1904eb3a`，参数表共 47 列。纯面积策略选择列 0（约
4721 平方米的垂直面）；它没有窗洞，而列 31、5 等带窗立面被舍弃。六槽位本身
没有丢失，错误发生在代表表面的选择阶段。

新逻辑在 `facadeCoverage.ts` 中按每个候选的真实 Base/Top UV 每米变换，对
32 米正方形做 48×48 抖动采样。对齐生产 shader 的 `fract`、signed region、
各图集半 texel 钳制、row3 padding、Base alpha clip、Top tint alpha 混合，
最后以 `1 - blended shaderMap.a` 估算窗洞/内景覆盖。只解码 alpha，Canvas
预乘不会损坏所需数据；每种材质的两张遮罩只解码一次。

候选面积至少为最大立面列的 5%；窗洞覆盖至少 2%，且不低于有效候选最大覆盖
的 20%。合格列按 `area * sqrt(windowCoverage)` 排序，兼顾主体面积与窗户，
避免微小玻璃装饰抢占整个立面。没有有效窗口时回退面积策略。图像解码失败也
回退面积策略；此时覆盖诊断为 0，不代表资产本身一定没有窗户。

玻璃可来自 Base，不要求 Top 开启；大 padding 也不一律视为关闭，常量或近常量
Top UV 必须参与实际计算。屋顶选择不受窗口优先策略影响。

真实数据通过生产分析、GLB 生成和 building4 WebGL 渲染，结果为：

| 资产                             | 修复后立面列 | 估算窗洞覆盖 | 结果                                       |
| -------------------------------- | -----------: | -----------: | ------------------------------------------ |
| 砖墙住宅 `40a2a11f:10daf7bf`     |           31 |        4.88% | 砖墙上恢复窗户；屋顶列 19                  |
| 金属住宅 `41e1c000:5a6ec67a`     |           34 |       18.44% | 金属墙板上恢复窗带；屋顶列 10              |
| 全玻璃办公楼 `61f0c000:1d261fdd` |            7 |       67.60% | 保留 Base 玻璃幕墙，Top 覆盖为 0；屋顶列 1 |

每个样本 456 个三角形，WebGL 程序均可运行，无 shader 错误。证据保存为
`tmp/procedural-windows-fixed.png` 和 `tmp/procedural-windows-webgl.json`。
复现页面仍为 `tools/procedural-material-webgl.html`，新增依赖
`tmp/procedural_windows/10daf7bf` 提取目录，并对三个真实样本作窗口/玻璃断言。

28 项程序化建筑相关测试覆盖遮罩混合、Base 玻璃、镜像区域、padding、常量 UV
刀带、透明裁剪、小装饰排除、无窗口/解码失败回退及现有 UI/生成链路。
这些覆盖率是选择启发式，并不等于整栋源建筑的实际开窗率；当前仍是代表立面
迁移，不复制原建筑各面不同的窗型、精确楼层分布和装饰物。此次验证在浏览器
运行真实提取资产，未执行桌面 Tauri 的完整点击流程。

## 体块生成器重构（2026-10-22）

生成器新增 `blockMass` 模式，尺寸单位统一为米，体块尺寸上限为 1000m，位置范围
为 ±2000m，最多 16 个体块和 32 个挖空。每个体块独立保存中心、宽度、进深、高度
和 Z 轴旋转角；挖空使用宿主体块的局部坐标，支持贯穿屋顶/底面的庭院，也支持只
切出墙面凹槽。体块先做 union，再对各自挖空做 subtract，`solidGeometry.ts` 输出
边界面，因此相交体块不会留下内部墙或重复屋顶。

面板提供单体块、Y 形和庭院预设，并允许添加/删除体块、设置每个体块的尺寸/位置/
角度/底标高，以及设置挖空的尺寸和 XYZ 偏移。旧的开间生成器仍保留为没有
`blockMass` 的文档兼容路径。未绑定 Property 材质时，体块屋面使用 roof 槽的
默认色；绑定后，水平边界面使用源材质的屋面代表列，垂直边界面使用窗户感知的
facade 代表列。

屋面 TGI `00b1b104:42e1c000:4a8f5ef9` 的跨包探针命令使用 Game、Graphics、EP1
和 DLC0 四个 package，解析到 LOD1 模型 `0x2F4E681B:0x00000000:0x4A8F5EF6`，
材质段 13，6 个纹理槽（slot0 参数表、slot1 tint、slot2 normal、slot3 shader、
slot4 palette、slot5 interior）和 40×4 参数表。屋面候选列 28 的面积约 2197，
其 regionXform 为 `(0.22275, 0.20745, 0.76196, 0.14182)`，Top 变换为
`(0.08231, 0.14349, 0.65072, 0.19605)`；合成图已保存到
`tmp/procedural_roof/4a8f5ef9-full/compose_albedo.png`，候选对比图为
`tmp/procedural_roof/4a8f5ef9-candidates.png`。之前屋面纯色的直接原因是只打开
Game 包导致 slot1–5 查找失败；跨包加载后六槽位均可读，不能再把缺槽产生的黑图
当作材质结论。
