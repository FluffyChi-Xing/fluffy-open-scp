# 从 ER2 与 Property 提取可移植的建筑行为

## 配方的单位

建筑行为可以用一组可追溯的原版记录表达。以行为入口为种子，从编译后的 ER2 追踪规则、事务和状态变更，从有效 Unit Property 追踪注册这些入口的 bundle、资源槽及参数绑定。外部接入由资产的 Lot 和宿主 Unit 提供。这样可以沿用原版规则 ID 与 Property 记录，同时让建筑外观和菜单独立选取。

构建时先按引擎的加载路径解析有效 Property，保留各列的来源、顺序与排除项。可达性从 Unit 的核心规则、事件规则、sink 绑定分别开始，包含成功和失败分支及其有效特化。对每个读写标记范围（本地、事务或相邻单位、全局、地图），把本地必需依赖追到具体 provider；将城市供给、外部目标与路径作为配方声明的前置条件。规则读写涉及可选分支、运行状态、排班和道路容量，静态闭合的结论仅覆盖已经解析的依赖。

引擎依据 `07E0AD23/24/08635E12` 声明资源、容量及初值。随后 `AddBundlePropOverrides` 读 `0A6FE749/4A/4D` 容量绑定及 `0A6FE74B/4C/4E` 初值绑定，查已存在的 bin 与 Unit 的有效 Float；条件满足才改写，初值还会钳制到容量。规则本身另有读取 Property 的路径，例如 `CanRunRule` 的 Property 型 `mApplyResource` 读取整数。因此类型和绑定方式要按消费者核对。参考 `SimCity.unwrapped.exe.c:695679`、`:698468`、`:699034`、`:700164`。

## 观光

| 阶段 | 原版接线 | 可观察量 |
| --- | --- | --- |
| 城市供给 | `E15369A2 → AE3774FA`，从 `0E542F39` 和 `0D8C29F6/FE/0D8C2A01` 的绑定发布吸引力与三档配额 | 本地和全局吸引力、各档配额 |
| W2 派发与接收 | 城市规则 `13FC9444` 派发 W2，`75D22FD1 → 64E8EB51` 接收，扣事务载荷、本地 `SouvenirsW2` 与 `OpenShoppers`，增加 `TouristW2`、`TotalShoppers` | 进城计数、实际送达、占位、纪念品消耗 |
| 营业周期 | 同一个 W2 bundle 注册 `414F8467`、`DB294BAB`、`9CF147E7`，它们访问本地 `4B16C93D` 并改变纪念品库存。三档接收 bundle 也声明共享的 `OpenShoppers` 与 `TotalShoppers` | 营业期可用库存、关闭或周期切换后的库存与空位 |
| W2 酒店 | `729A6626 → 774570F5` 办理入住，`8645F30B → 75167B09` 接入后续处理，其中一条失败回退路径到 `6EA6E257`，归还空房并派发游客，候选包括 `75D22FD1` | 入住、空房扣减、离店后归还、转送成功或回退 |

**四个观光 bundle 仍有底座依赖。** 从零售 Property 回读 `E15369A2` 与 `75D22FD2/1/0`，这四个 bundle 均无本地 `4B16C93D` 声明，W2 的三条周期规则却访问它。东京塔 `084DB48F` 有效表由 `3A70FAA2` 声明该 bin，普通商业 `C05FED42` 的有效表由 `D07C5A04` 声明，另见 `30645625` 的原版声明。这给出了一个可检查的宿主依赖，尚需局内测量它对各分支的影响。W2 到达成功后的 `2B3A2553 → D85F9F5E` 还分别触及本地 `0BFA0784`、`5FFA86B9`。普通商业从 `362087BD` 声明这两项，东京塔的有效 bundle 表未找到这两项声明。构建检查要区分要求保真的主路径与供体本来允许跳过的分支。

**共享列要在组合前解析。** 三档接收 bundle 把 Float `0E2660C6` 写入各档纪念品容量；酒店 `729A6626` 用同一列初始化 `OpenGuestsW2`。当前 `native-tourism-v1` 同时挂载观光与酒店时写入 68，这是一个参数同时流入两个用途。三档也共同将 `0AD6A725` 写入 `OpenShoppers`。接收 bundle 对 `0EF29855/56/57` 分别另有初值绑定，东京塔叶与直接 parent 均缺这些列，综合娱乐样本 `3CE0F852` 叶显式写 0/100/300。保留各供体的缺省处理。若独立提供房间数和纪念品容量，需另行验证可分别映射到两个参数的原版接线或新绑定。

第一份提取候选用普通商业 W2 供体或东京塔接待，保留对应的运营底座并暂时关闭住宿。验证供给、送达、接收、周期重置后，再把住宿作为一项独立可观测能力。现有 `behavior_tourism.rs` 已显式挂载四个 bundle 并验证入口，且该 profile 本身无需设置东京塔 parent，适合用作静态检查的首个对照对象。

两者都对同一组八个资源槽做容量与初值绑定，使用各自的 Property 列。小学的 `0AD7FAC9` 绑定的是八个时段需求槽；接收 sink 检查实时 `SpotsForKids`。住宅规则 `9CFEB042` 的目的地表包含 `78B96709`。送达后 `B52C889D` 转换在途儿童，增加学生与在校计数并扣空位。配方还要覆盖时段放位、学习结算、离校和跨日清理。两族共享的 `C193A5BB` 是每日统计清理入口之一。

原版学校的 `7E4B99E5` parent 提供通用底座与事件，学生接线来自叶级 bundle。首个候选可沿用小学叶的行为记录，显式声明仍需的通用事件、学校分类、路网和学生派发兼容性，保存看板与菜单作为呈现契约。教育流程和招工可分别列出依赖，按所选供体核对是否有运营条件互相引用。社区大学另用自己的七项教育 bundle 和八列初值作为起点。s14 已有大学在游戏内工作的记录，尚无本轮候选宿主移植的动态证据。

## 住宅

- **入住与空置状态。** 科潘直填使用 `999F8484 → BBAAD3D1 → ED171D40 → … → 337A4D2F`。巨塔 W1 公寓的同一接收项使用 `78A730CD → BBAAD3D1 → 81AA8640 → … → 1788982F`，`EBFC1753` 提供容量与状态。两条入住路径要随宿主选一条，显式验证排除表和空置位。当前工作区的 `behavior_residence_fill.rs` 已按这个方向替换入口，并要求其余住宅底座可用。
- **居民经济。** 科潘 `AB9A0A3E` 声明居民、工人、消费者与孩童的槽和多个返家 sink。它从 `0A7917CB`、`0E33502E`、`0E335022`、`0A7917CC` 读取对应容量；有些原版绑定倍率不同，保留整行。消费者派发 `7A41EB3A → 80D55C93 → 91BF9728` 把人和钱送入事务，返家 `487E1CC6/9B6FB379 → 104D6998` 恢复本地人口和消费者计数。通勤、返家、幸福及迁出也需核对对应的规则和资源。施工、外部接入与可达的就业和购物目标属于宿主或城市依赖。
- **移植判据。** 先复用科潘的居民经济和一条已追到的入住路径，保留依赖的服务与状态事件。用空置到入住、工人通勤返家、消费者购物返家、人口流失后的空位恢复验收。原版科潘证明地标身份能承载住宅，巨塔接线在地面宿主上的回读只证明构建数据。

## OpenSCP 的落点

先在现有处理器旁提供只读配方审计。从最终 Unit、Lot、所用原版 Property 与 AEB 建图，输出每条绑定的字段类型、来源、写入目标及实际可达的入口。构建期可以逐步启用有原版证据的校验，包括缺失 bundle 或必需 bin、bundle 被排除、配对数组不完整、参数类型错误、同一 Float 的多重用途、同一 sink 的多重规则绑定。重复声明与共享 bin 的原版组合应保留，诊断说明谁写、按什么顺序写以及语义是否兼容。界面可沿用同一份依赖数据，从字段跳到其 bundle 和规则，显示缺失的接收端或宿主条件。

离线检查能重现有效接线和依赖来源。行为验收需要用户在独立菜单资产和隔离城市里观察完整周期，包括停止与重新运营。现有处理器作为对照，分别验证同一行为配方能否在不同宿主成立。
