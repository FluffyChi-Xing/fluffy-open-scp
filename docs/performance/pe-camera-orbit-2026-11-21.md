# PE 镜头转动：近景像素负载与自适应预算

## 指定建筑 00b1b104:42e1c000:2f0f5c25

用户反馈：距离建筑越近，转动镜头越迟滞。只读导出此建筑的现有 render_fixture：136×136 地块、148 单元、6 个贴花；接入真实 prop、四个树形模板和 SIMF 小人部件。视觉核对为截图中的同一商业建筑。夹具及图片只写入工作区 tmp，未修改游戏包、存档，也未启动 SimCity。

普通窗口（画布 1506×910、DPR=1）的隐藏 Edge / Intel UHD / ANGLE D3D11 未复现用户同等程度的卡顿。将同一场景的绘制缓冲设为 3840×2160 后，远景 GPU 中位耗时约 8ms，近景约 55ms，而 CPU 提交中位约 4ms，复现像素着色受限的近景迟滞。这是高像素负载对照，不能声称已复现用户桌面 WebView 的全部环境。

## 修改

- 新增独立的 `interactionFrameBudget.ts`，每个 viewer 单独持有状态。只有配置了交互像素预算的视口才启用自适应，不修改相机角度、输入倍率、几何、材质或着色公式。
- 拖动/滚轮交互中，连续三个慢帧才降低绘制像素比例。普通负载保持原比例；单次尖峰、静止后的长帧间隔不会单独触发降档。
- 一般慢帧分级调整；重负载直接降到半比例，避免连续三次中间尺寸的缓冲重分配。下限为 0.5，原始交互配置低于 0.5 时不升高它。一次手势内不来回升降，避免清晰度振荡。
- 松手后沿用原来的 180ms 恢复机制，恢复完整 DPR 与阴影更新。截图路径仍使用完整像素比例。
- 将原 `disposeObject` 等价移入 `viewerObjectDisposal.ts` 并保留原导出，保持 viewer 在 1000 行以内。

试过仅在运动时关闭近景 Catmull-Rom 重建采样，对指定建筑没有稳定收益，已撤回；没有保留这项材质质量变化。

## 频闪回归修复

用户反馈移动镜头时短暂频闪。上一轮自适应代码在 renderLoop 已经绘制后调用 setPixelRatio，这会重置并清空刚画好的 WebGL backing buffer，下一 rAF 才补画；恢复定时器也直接改变画布尺寸，存在相同的空帧窗口。

新增 `framePixelRatio.ts`，所有交互降档/恢复只登记期望比例，下一次实际绘制时同步执行 resize + render。后到的拖动请求覆盖尚未绘制的恢复请求；相同比例不重复重置缓冲。截图完成后的比例恢复也排到下一次绘制，保留待执行的期望比例。

9 个相关测试通过，覆盖帧间不清空、恢复/新拖动交错、完整比例和阴影恢复、原有输入与帧预算。类型检查、修改文件 ESLint 和 diff 检查通过；viewer 保持 999 行。

真实 Edge WebGL 回归（`tmp/pe-flicker/result.json`）：三个比例 0.8 → 0.5 → 1 的完成帧中心像素均为 `[119,204,68,255]`；旧式绘制后改尺寸的阳性对照为 `[0,0,0,0]`，确认检测能捕获清空缓冲。这项检查针对空帧时序，不替代完整桌面交互验收。
