# PE 渲染切换性能调查（2026-11-21）

验收资产：`D:/openscp/mods/泡芙顾问有限公司`。尚未完成修改后的真实 WebView/GPU 冷启动验收，1000ms 目标尚未证实。

## 修改与依据

- `prepareShaders` 原本调用同步 `compile`，而装配不等待其结束就放行首帧。改用 `compileAsync`，与地面合成并发等待，保留过期与超时退出。
- `enhanceTintDetail` 原本在 Worker 返回后逐像素处理输出图，占用 UI 线程。原函数迁至独立纯模块，改在 Worker 内完成；主线程异常回退调用同一预览函数，保留旧导出兼容。
- 每张贴花原本重新验证全部接收面顶点，再对全模型执行裁剪。新增视口持有的 BVH 索引，按 geometry/position/index/normal 身份及版本失效。候选面恢复原始顺序后仍使用 Three DecalGeometry 精确裁剪。每接收面最多保存 16 个 CPU 投影模板，返回独立克隆，卸载清理索引。
- 重建合并、串行化与卸载取消从视口拆至 `sceneRebuildScheduler`。

取景分组、轴向、placement 矩阵和装配末尾 updateMatrixWorld 保持原实现。未修改资产文件或游戏目录。

## 验证

20 个测试文件、123 项测试通过（含单独运行的异步编译等待守卫）；TypeScript 检查与改动文件 ESLint 通过。

几何对拍覆盖索引/非索引、接收面旋转和非均匀缩放、重复投影缓存；缓存失效和非法顶点拒绝有守卫。Worker 预览与旧合成后增强流程的像素输出对拍一致。新增调度合并、串行和卸载取消测试。

8 万三角形、20 张局部贴花的独立合成基准：一次单独运行旧路径 579ms、新冷路径 268ms、重复约 2ms；最终并发回归运行约 1680/383/2ms。负载影响显著，这些数字仅代表贴花 CPU 阶段，不能当作整个场景切换耗时。

安装版数据库历史最后一次 render_mode 样本为 scene_rebuild 1289.9ms、ground compose 1192.8ms；尚未确认该样本属于泡芙资产。原有 span 未覆盖首次 GPU draw，不能据此解释数十秒冻结。数据库仅通过临时副本读取，副本已清理。

## 待验收

用新版实际 WebView 打开泡芙资产，记录首次白模到精细、精细到白模、重复切换及编辑后切换。测量点击到完整首帧的耗时、主线程长任务，检查贴花、地面、选择/拖拽、撤销、LOD 和语言切换。驱动首次编译、GPU 上传或 IPC 解码仍可能使冷切换超过 1000ms。

## 第二轮：真实资产地面与首帧上传

用户目测上一轮未发现回归，但改善不显著。进一步读取真实资产：mask/surface/normal 均为 1024×1024，精细输出 2633×2355，边框高度为 0.5。

- 新增精确地面快速路径：预计算图案采样的逐轴坐标和权重；保守检查四分之一 texel 导数覆盖范围，仅在所有通道都处于相同 smoothstep 饱和区时跳过恒为零的高度差。保留原路径用于差分验证，不改变分辨率、阈值、材质或高度公式。
- 使用真实 PNG、原始 mask.rgba 和 lot 参数测量，原路径约 1132–1325ms，新路径约 861–1013ms，albedo/normal 全字节一致。这只是地面 CPU 合成，不代表 WebView 首帧。
- 白模期间异步预计算精细地面，不更改当前材质、不上传 GPU；模式切换与预计算共享在途 Promise，缓存清理后过期任务不能重新填充缓存。
- 修复预热遗漏 tint 自定义 uniform、ShaderMaterial uniform 和 uniform 数组贴图。自定义纹理登记使用非枚举 Symbol，不进入 userData 克隆/序列化。
- 精细首帧之前分批上传贴图，每批约 6ms 后让出任务；补充完整场景的异步预编译，覆盖装配完成后才存在的地面/贴花材质。单张纹理上传和驱动工作本身无法保证在 6ms 内结束。

复现 CPU 基准：`node scripts/benchmark-pe-ground.mjs [资产目录]`。脚本只读资产，产物写入工作区 tmp/pe-ground。

第二轮相关回归共 23 文件、127 测试通过；其中快速合成对拍包含 36 组输入（随机/软渐变/平区、边框宽度 0/0.0375/0.48/0.7、退化尺寸），另有预计算共享与首帧上传让出/取消守卫。

1000ms 整场景目标仍待真实 WebView/GPU 运行验收。预计算未完成便立即切换时仍需等待剩余计算，不能把白模期间做的工作视为消失。
