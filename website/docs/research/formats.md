# 从 DBPF 开始读懂资源

> 格式入门 · 文档摘要 · 整理于 2026-10-15。依据项目资源格式速查与 README，不将样本覆盖率作为所有游戏安装的保证。

`.package` 是资源容器，不是一种单一模型或图片格式。理解它的第一步，是将“找到字节”与“理解字节”分开。

## 容器负责定位

DBPF 的索引记录资源标识、数据位置、大小与压缩信息。**TGI** 由 Type、Group、Instance 构成，用于标识和关联资源。

| 字段 | 用来回答的问题 |
| --- | --- |
| Type | 这是什么类型的资源？ |
| Group | 它属于哪个分组？ |
| Instance | 这是哪个具体实例？ |

## 压缩层负责恢复载荷

当索引标记资源经过 RefPack 压缩时，需要先解压，再交给对应的格式解析器。容器索引、解压结果和资源内部结构应分别验证，避免把某一层的失败误认为另一层的问题。

## 资源类型决定下一步

- **Property**：属性与资源引用，连接模型、地块和模拟参数。
- **RW4**：模型、纹理、骨骼和动画等 section 结构。
- **Raster**：位图与相关元数据，可能需要特定像素格式解码。
- **文本与媒体**：文本可直接查看；部分音视频需要外部解码工具。

## 名称是帮助，不是格式证明

描述符库可以把数字 ID 映射到可读名称。归档研究也记录过类型标签与实际内容不一致的情况，例如标为 Javascript File 的部分资源实际是 UI 布局 JSON。

因此，文件名、标签与扩展名是入口；真正的判断还应结合头部、结构、引用关系和解析结果。
