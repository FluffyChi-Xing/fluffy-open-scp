# SC5 Asset Packager 0.8.0（更新）

直接双击本目录的 **SC5 Asset Packager.exe**。运行依赖已内置，无须复制开发目录，也不要求安装 Python。本次按当前发行要求只提供 EXE，不另生成压缩包。

## 使用建筑功能

1. 打开已有项目或 Blender 导出的资产文件夹。
2. 分别选择“菜单位置”和“建筑功能”。例如：菜单放在教育，功能选择基础公园，仍然使用公园行为，不会提供学位。
3. “旧版兼容”保留先前的行为及打包方式。旧项目缺少新字段时默认采用它，不会自动切换。
4. “基础公园”读取并校验原版低收入基础公园行为，接入对应规则与幸福度相关参数；保留自制模型、材质、窗户、地面、道具和灯光。
5. 造价、维护费使用上方设置。其他行为参数采用固定原生配方，暂不开放自定义地价、幸福度半径、学位、产水量等未经验证的配置。
6. 点击“检查资产”可检查功能依赖；“生成计划”只检查并写报告；“导出 Package”生成成品。

**成品在所打开项目的 `output` 文件夹。** 导出完成会显示具体文件路径，也可点击“打开输出文件夹”。输入资产与游戏原文件不会被安装器改写；程序不自动向游戏目录安装内容。

## 第一轮测试包

位置：`SC5 Asset Packager/Projects/BehaviorQA080/output/SC5_Native_Park_Function_Test_0.8.0.package`。

该测试资产采用小屋、地面、一棵树和四盏装饰灯，菜单位置为公园，造价 400，维护费 40/小时。重点是验证新公园行为，不是新的大楼外观测试。

建议在测试城市新建，不直接替换重要城市中的旧建筑。新公园预设与旧版兼容预设使用不同的资产身份，切换功能后请重新建造；不要用旧建筑存档判断新预设是否生效。同一项目应避免同时安装不同版本输出包。

建议依次检查：建造/选中、访客与营业状态、周边幸福度变化、手动停用与恢复、保存重开、拆除，并以原版基础公园作对照。原版行为已经写入并通过离线核验，**实际幸福度、地价或访客变化仍需游戏验证**，不能用菜单图标或信息文字代替效果测试。

本版不更改窗户昼夜、视差、拆除动画或装饰灯控制机制。手动停用后装饰灯不灭的问题仍待专项研究。

## 诊断资料

项目的 `reports/behavior-preflight.json` 记录原生依赖核验；`reports/native-backend-result.json` 记录实际打包的功能和回读结果；`reports/build-result.json` 列出成品路径。

如果提示公园功能资源版本不一致，请保留报告，先核对游戏资源版本。本版不会忽略差异继续套用配方。
