# 打包器 0.8.0：首个建筑功能配方实现

2026-11-02。本次由研究转入实现，范围为单一基础公园配方；教育、供水等完整服务尚未接入。

## 新发现及问题出处

对 `engine/tested-unit.bin` 与原版 `00B1B104:40E0C000:59292C11` 的完整继承展开做逐字段比较，结果保存在 `park-unit-differences.json`。虽然两者拥有相同的 205 个静态候选规则，但现有基准将 `0E965A70..75`、`0E965BE0..E5` 十二项专化属性置零；原版对应交替为标量 1 和向量 [2.5,2.5]。

结合上一份报告对 HappinessFromPark、SadnessFromPark 及规则属性专化的追踪，这解释了为什么“保留公园规则”仍不等于“原版公园作用完整”。本次恢复的是原生配方，不将 1 解释成“幸福度 +1”，也不将 2.5 擅自标成米数。

## 实现

- `behavior_profiles.py` 管理 `legacy-display` 与 `native-park-w1-v1` 两个模式，独立于 22 个菜单位置。
- 默认兼容旧项目，继续使用既有 tested-unit 行为和原先分类写入方式；不会静默恢复效果。
- 新公园配方展开原生 Unit 继承，保留 bundle 启用/排除、资源绑定、原生岗位、访客及效果参数；不重新拼接猜测的规则列表。
- 保留自制资产的 Graphics 引用、名称和既有本地足迹字段 `0ACFFA64`。去掉原版 Parent 和解锁字段 `0BF5D2E3/4`；不移植原版建筑地面、树木、交通布局或默认子模块。
- `behavior_native_profile.json` 存储 46 项已研究源资源的 SHA256，包括原生 Unit 继承、bundle 祖先及编译规则主资源。只存证据，不内置原游戏资源内容。
- 打包前读取安装资源，资源缺失、哈希不同、继承循环或默认模块不支持时停止，避免昂贵转换完成后才发现功能配方不适用。
- 原生规则保持游戏内共享引用，不向输出包写全局规则资源；包只包含自有资产资源。选择功能不会改变贴图/视差转换。
- 回读时逐项核对最终 Unit 的预期原始记录，包括效果字段、分类、费用与原生行为字段；模型引用和本地化名称另由已有资产身份检查验证。
- 新模式加入资产身份派生依据，避免与同项目同版本旧模式的身份混淆；因此测试时需要新建建筑。
- 构建脚本已取消自动生成便携 ZIP；仍生成独立 EXE。

## 边界

公园配方以原版低收入基础公园为证据。岗位等使用原版默认值，不开放未知语义滑块。功能仍标注 `runtimeVerified=false`，不能声称已在游戏中验证幸福度或地价增长。

匹配的是核心 Game/App/Graphics 与文件名数字最大的 Scripts 包，其他模组的实际覆盖顺序不在本版模拟范围内。若未来支持更多游戏版本，应新增版本化证据，而不是关闭哈希检查。

## 验证与产物

24 项自动测试通过，包括旧版字段兼容、功能字段写入、错误/缺失规则资源拒绝、回读篡改拒绝、未知功能与猜测参数拒绝，以及菜单、朝向、内景、道具、灯光和项目打开回归。

源码界面验证：预设切换与保存重开、菜单/功能分别保存、控件可见性正常。实际 EXE 验证：真实 Tk/WGL 预览通过，包含一棵树、四盏装饰灯；实际 EXE 编译测试包通过，而不只是从源码打包成功。

测试包约 21.6 MB。完整回读检查包含：材质、房间状态、灯光/道具字段、几何数量、朝向、选择碰撞、独立菜单/单位/图形引用、依赖及地面。运行期间原游戏文件元数据和选定四个源包哈希保持不变，具体值见本轮构建的 `游戏目录只读核验.json`。

证据入口：`SC5 Asset Packager/Projects/BehaviorQA080/reports/`；冻结 EXE 预览报告及 GUI 验证在 `SC5 Asset Packager/release/0.8.0/`。最终交付哈希与验证汇总见本目录 `delivery080.json`。
