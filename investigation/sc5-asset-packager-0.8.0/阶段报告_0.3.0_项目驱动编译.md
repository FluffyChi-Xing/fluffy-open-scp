# 0.3.0 项目驱动编译阶段报告

日期：2026-11-01

## 问题出处

旧窗口仅管理项目清单。原 `backend_native.py` 调用的研究脚本仍固定了大连希望大厦输入、材质数量、地块分辨率和部分属性。改名复制输出不能证明新资产被编译，不能用于任意项目。

## 本阶段实现

新增 `backend_compile.py`，复用并封装本地研究中已验证的单网格/原生材质转换。通过 `prepare_engine.py` 将需要的解析器、RW4 转换器、原生属性编码器、兼容模板及验证器整理到 engine，随 EXE 分发。构建时不依赖外部研究脚本路径或 Python 安装。

流程：项目清单 → 校验唯一 LOTM9 和同名地块包 → 计算输入哈希并保存快照 → 从 LOTM 提取几何、六槽材质与参数 → 建立单网格、碰撞和表面/房间图集 → 重建地块数字 Raster → 生成独立菜单/单位/资产标识 → 写入 DBPF → 两套读取器回读 → 检查资源链、原生属性、纹理和碰撞 → 核对源三角面及费用 → 输出 Package 与报告。

费用来自项目配置。教育分类取原生教育菜单类别字段，公园使用已验证类别；保留完整兼容生命周期，避免回归到“建造预览正常、落地后消失”的简化单位配置。每个项目使用独立命名空间分配资源标识，并扫描本机已有资源冲突。

## 材质与体积

保留原生参数、窗户视差及日夜状态数据。沿用已验证的相对浮雕转换、Office 旧状态布局修复与透明 Top 后备图块。

`compact_2048` 将超过 2048 的表面图集缩小，各通道独立过滤。RGBA 在这里包含数字控制数据，不能使用会预乘透明度的普通 RGBA 缩放，否则透明像素中的 RGB 控制值可能丢失。参数和房间图集不使用此表面缩放。

## 实测证据

实际输入为 `资产打包/老式大楼/Box001.002_原生` 配套文件。

- 读取 109 个材质组，源模型及最终模型均为 57,430 个三角面。
- 教育分类原尺寸构建：295,000,002 字节（约 281.33 MiB）。
- 公园分类紧凑构建：93,673,602 字节（约 89.33 MiB），相对缩减约 68.25%。
- 紧凑构建由 EXE 自身执行，退出码 0；没有调用本机 Python 来执行编译。
- 最终 0.3.0 EXE 再次生成教育分类紧凑包：93,673,407 字节，造价 50,000、维护费 100/小时，完整 Package 验证通过；启动后的实际窗口标题为 `SC5 Asset Packager 0.3.0`，窗口有响应。
- 测试造价 12,345、维护费 67/小时从最终单位属性正确回读。
- 输出回读、独立 DBPF 读取器、菜单→单位→资产→四级 LOD、地块引用、原生属性编码、碰撞范围、材质依赖验证通过，未解析的强类型引用为 0。
- 游戏文件元数据快照及四个主要源包哈希在构建前后保持一致；未安装新包。
- 既有打开资产目录、重复打开、保留输入及失败切换等回归检查通过。
- 不支持的分类、模拟功能、负费用及实验性几何/材质策略在开始构建前被拒绝，未产生输出目录。

详细证据见 `Projects/OldTowerCompact/reports/native-backend-result.json` 与其中指向的候选包验证报告。报告记录实际输入哈希、项目设置、成品包哈希、材质组和三角面数量。

## 仍待验证及边界

这是通用 LOTM9 编译的首个测试版本，未宣称覆盖所有 Blender 导出形态。最多 128 个材质组，要求原生 UV/切线及单列材质参数。只支持教育/公园展示菜单，不提供自定义模拟服务。生命周期依赖已验证的通用兼容程序集及本机原生规则/共享材质；并非重写游戏渲染器。

四级 LOD 当前保留同一模型，拆除动画兼容性和减面仍是后续工作。本阶段新资产的游戏内效果未验证，`runtimeVerified` 保持 false。缩小图集可能损失细节，昼夜、浮雕、地面远景需由用户进行游戏实测。

程序全程离线运行，没有新增 WebSocket 或网络服务。后续若接入服务，按用户要求使用 HTTP。
