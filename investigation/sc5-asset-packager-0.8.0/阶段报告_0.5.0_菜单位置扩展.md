# 0.5.0 菜单位置扩展：研究与测试说明

日期：2026-11-01。

## 更新范围与使用

打开同目录的 SC5 Asset Packager.exe，在“资产与游戏属性”中的“菜单位置”下拉框选择目标位置，然后导出 Package。分类选项改用中文，同时显示游戏内的查找路径。旧教育、公园项目可直接打开；三维预览、临街朝向、自定义菜单图标及成品目录提示继续保留。

本版接入 22 个位置，新增 20 个。教育、公园沿用此前已通过游戏测试的入口。新增位置已通过原版资源和导出回读核验，尚待用户在游戏中验收。保留当前展示建筑的单位运行配置，不新增学校席位、消防车辆、医疗服务、供电量或其它服务参数。

## 出处与原理

1. 前期研究已经区分三条链路：Menu 决定入口；Unit 决定单位运行与费用；Asset/LOD 决定可见模型、地面和交互。教育菜单中的大厦曾因混改主体装配、模拟类别而产生不可见问题，因此本轮只操作 Menu 的归属与排序。
2. OpenSCP 的 `docs/re/menu-item-relations-20261018.md` 与 `menu-editing-closed-loop-20261017.md` 指出：`0DB9FC63` 是菜单归属 Key 数组；`00B2CCCB` 是继承 Parent，二者不能混用。公共交通顶层 `CBC27856` 和公园顶层 `899BEA70` 由运行时装配，不能只把它们当成普通静态容器写入。
3. 本轮使用 OpenSCP 已提取的 tools.json、locale 和分类布局作为查找线索，再从本机 SimCity_Game.package、SimCity_App.package、SimCity_Graphics.package 读取实际原版 Menu，逐个确认目标归属。没有仅凭文字或猜测编号接入。
4. 新增 `menu_locations.py` 作为唯一菜单目录，界面、CLI、项目 Schema 和编译器共用。每次实际编译重新确认所选位置的原版样本存在、其 `0DB9FC63` 包含预期 Key；不一致时停止并给出具体提示。
5. 新位置写入单个已确认的原生归属。教育保留原有测试入口的额外归属，保持旧项目兼容。排序继续扫描已索引菜单的目标成员，取其最大排序值后追加 100，并保证归属与排序数组等长。
6. 最终回读 Package 中的 Menu，核对实际归属、数组长度；回读 Unit，确认其既有模拟类别未被菜单选项改变。构建计划、结果及原生核验报告记录所选位置和原版依据。

## 验证证据

- `native-menu-audit.json`：22/22 位置的原版样本、来源包、原版载荷 SHA-256、归属数组和追加排序均已核对。全部原版资料为只读。
- `menu-ui-qa.json`：22 个中文选项逐个选择、保存、重新载入成功；费用、朝向、材质策略及已有运行设置未改变。
- `regression.log`：10 项回归测试通过，覆盖原项目打开、编译限制、朝向与昼夜、输出路径、新菜单序列化、原版依据不匹配拒绝、教育多归属兼容。
- 完整医疗导出：使用老式大楼真实资产，57,430 个三角形、109 个材质组，完成几何、材质、地块、菜单和单位导出，离线回读通过。
- 最终 EXE 完整消防导出：对同一资产仅切换菜单位置，完成导出并得到 PACKAGE_VALIDATED。
- `menu-only-package-comparison.json`：医疗与消防两个完整包的 17 个资源标识相同，只有 1 个 Menu 资源改变；变化仅为 `0DB9FC63`（归属）与 `0DC1E3E0`（排序）。Unit、模型、材质、地块、图标和文字资源全部逐字节相同。这是本轮“菜单位置与功能配置分离”的直接证据。
- `frozen-preview-qa.json`：新版 EXE 实际建立窗口和 OpenGL 上下文，显示消防菜单、22 个选项，真实模型及自定义图标加载正常。
- 测试包大小 93,673,910 字节，约 89.33 MiB；菜单扩展没有复制额外模型或原版游戏资源来扩大包体。

完整导出测试项目位于 `SC5 Asset Packager/Projects/MenuQA050`。其中 `health-reference.package` 和 output 中的消防包是相同资产标识的两个对照版本，不能同时安装。这些是程序核验材料，不是正式美术资产发布包。

## 游戏内验收步骤

1. 用新版程序打开自己的资产项目，选择一个新增菜单位置，核对名称、图标、费用、朝向，再导出。
2. 完全退出游戏后，手动安装本次生成的 Package；同一资产的新旧包只保留一个有效版本，原游戏包保持原样。
3. 在测试城市的对应菜单或子菜单中向后翻页，核对图标、名称、造价、预放置和最终楼体。
4. 验证普通选择、直接拆除、保存后重新载入，以及白天、夜间、近远景显示。
5. 如有异常，记录所选菜单位置、Package 名称、是否装有菜单模组，以及问题发生于菜单查找、预放置还是建成之后。

本轮未自动安装 Package、未启动游戏、未修改游戏文件或存档。新增位置的原生结构核验不能代替游戏实测。住宅、商业、工业自动生长流程、道路与分区工具、灾难工具和区域大工程不在本次菜单位置更新范围；不把它们冒充为已经接入的建筑分类。

## 后续开发接口

菜单目录保留稳定配置键（如 health、fire、airport）和中文名称；`category` 继续表示菜单位置，未来的服务功能应使用独立字段与独立验证配置。下一步可在新增位置实测通过后逐步记录验收状态，再单独研究服务能力，避免通过更换菜单归属推导模拟效果。
